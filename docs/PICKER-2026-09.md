## §0 Summary and decisions

**In scope:** three gaps in the picker — it emits **cosmetic rules only**, generates **no procedural selectors**, and offers **weak candidates** with a page-visible inline-style preview. This plan closes them across **seven concerns** in two ownership groups that run in parallel:

- **Picker group (owns `src/content/element-picker.js` + `.test.mjs`, serial chain):** `PK1` honest save, `PK2a` network-candidate helpers + escaping, `PK2b` plumb the candidate kind through save/preview, `PK3` procedural candidates, `PK4` stronger CSS candidates, `PK5` reload-faithful preview. (`PK2` was split into `PK2a`/`PK2b` on the recheck's Rec4.)
- **Service-worker group (owns `src/background/service-worker.js` + new sw-harness tests, serial chain):** `SW1` the renderer-facing trust gate on `APPEND_USER_FILTER`, `SW2` honest drop-reporting on the WASM-down path.

The two groups touch disjoint files, so they run concurrently; within each group the concerns are one-commit-each on a shared file and therefore sequential.

**Blast radius.** `element-picker.js` is **Low** by the §3 map (it is in `src/content` but is UI, isolated from network/cosmetic correctness; it ships in `content.js`). `service-worker.js` is **High** — `SW1`/`SW2` each need a second reviewer.

**Rule 2 verdict (decided honestly): no picker concern trips Rule 2, so none needs a flag.** Every picker save already causes exactly one `APPEND_USER_FILTER` → one `updateDynamicRules` cycle, whether the saved line is cosmetic or network (`_applyUserFiltersNow` always clears and re-adds the user id range, verified). Network candidates change *what* rule is written, not *when or how often* the API fires; the cadence is one user-initiated save = one apply, unchanged. `SW1`/`SW2` add validation/reporting inside that same single call. No concern changes the frequency of `updateDynamicRules`, `registerContentScripts`, `executeScript`, or `updateContentScripts`. (`SW1` is still second-reviewed because it is a security-relevant change to a High-blast-radius file, which Rule 1 requires independently of Rule 2.)

### Decisions that need the user (recommendation in **bold**)

1. **Which elements get a network candidate, and how the URL becomes a pattern.** Recommendation: **offer a network candidate for `img`, `image` (SVG), `iframe`/`frame`, `video`/`audio` (and their `<source>`/`poster`), `embed`, `object`, and any element carrying a `background-image: url(...)`. Reduce the resource URL to `||<hostname><pathname>^` (query string dropped); if the pathname contains an ABP metacharacter (`$ ^ | *` or a char < 0x20), truncate the pathname at the first such character and emit the longest metacharacter-free prefix `||<hostname><prefix>` (no trailing `^`), falling back to host-only `||<hostname>^` only when nothing but `/` remains. Reject the candidate outright when `<hostname>` is not a plain DNS hostname or IP literal** (see decision below and `PK2a`'s escaping contract — the WHATWG URL parser lets a host hold `$ * , = { }`, verified by `recheck/probe-host.mjs`, so the host must be validated, not trusted). A truncated prefix is strictly narrower than the whole host, so the escape can never *widen* the block the user aimed at (reviewer's amended Rec3). Path-minus-query is specific enough to hit the ad and stable enough to survive cache-busting query params. Offer host-only and full-path as alternate radios; the dialog shows whatever line is produced verbatim and labels its real scope (prefix or host).
2. **Default scope of a network candidate.** Recommendation: **domain-scope it to the site being picked on (`$…,domain=<site>`), default ON, mirroring the existing "Apply only to `<site>`" checkbox.** A picked CDN path (`||cdn.example/a/x.png^`) blocked globally is a real cross-site regression (that CDN path may be used elsewhere); scoping to the initiator domain contains it. **Caveat the user must accept:** a `$…,domain=` network rule compiles correctly on the WASM path but is **silently dropped on the WASM-down fallback** (verified, §1). `SW2` makes that drop honest; without `SW2`, `PK1` cannot report it because the fallback never records it.
3. **Which procedural operators the picker generates.** Recommendation: **`:has-text()` (from the element's own visible text) and native `:has()` (for "the parent that contains this ad image" — native CSS in Chrome, no procedural machinery), plus `:upward(n)` only as an explicit "block the container" affordance.** Do **not** generate `:matches-attr`, `:xpath`, `:matches-css`, `:others`, `:remove-*`, `:matches-media`, `:shadow` — several are fail-closed/unimplemented in the engine (`cosmetic-engine.js` `_applyOp`; REMEDIATION-2026-09 C1a/C1b) and the rest are too niche for a point-and-click tool.
4. **How `:has-text()` text is chosen and escaped.** Recommendation: **trimmed, whitespace-collapsed `textContent`, truncated at the first `(`/`)`/`#`/newline/control char, offered only when ≥ 3 chars remain, `null` when the (post-truncation) text begins with `/`, emitted as a plain literal (never wrapped as `/regex/`).** The engine's `_applyOp('has-text')` reads a leading `/` as the regex form, so text `/.*/` would compile to a rule matching every element and blank the page (reviewer's REQUIRED 3, driven through the real engine in `recheck/probe-hastext.mjs`); refusing a leading `/` closes that. Truncating at `(`/`)`/`#`/newline also guarantees the argument cannot close the operator early or introduce a second rule type.
5. **How a network block is previewed.** Recommendation: **hide the element now through the same injected stylesheet `PK5` introduces, and label the candidate "Blocks the request — applies now and on every reload."** A network block only takes effect on reload (the resource is already loaded), so the preview cosmetically hides it and the label states the true mechanism.
6. **How a compiler-dropped rule is reported.** Recommendation (`PK1`): **`savePickerRule` inspects `res.counts.skippedNetwork`/`skippedRules` and shows the drop reason instead of "✅ Rule saved."** Today it checks only `res?.ok`, so a dropped line reports success (verified).
7. **`SW2` — widen the fallback vs. record its drops.** Recommendation: **record the drop (make `parseSimpleNetworkRule`-refused network lines count in `skippedNetwork`/`skippedRules`), do not port the whole `$domain=` option table into the fallback.** Recording is a bounded honesty fix; full fallback parity is REMEDIATION-2026-09 §7.3's follow-up. If the team judges the WASM-down window negligible, `SW2` may be **deferred**, at the cost of a network candidate saved during that window reporting success while being dropped.
8. **`SW1` scope — an ALLOWLIST, not a denylist** (reviewer's REQUIRED 1). A denylist is both bypassable and incomplete: JS `String.prototype.trim()` does not strip U+0085 (NEL) but Rust's `str::trim()` strips every `\p{White_Space}`, so `"\u0085@@||bank.example^"` fails a JS `startsWith('@@')` test yet compiles to a live `allow` rule (verified, `recheck/probe-cp.mjs`: stored code-point 0 is U+0085, `dnr:[{a:"allow",…}]`); and the privileged options a denylist would have to enumerate are open-ended (`$popup`, `$doc`, `$all`, `*$script`, `|http`, `/./`, `$csp`, `$removeparam`, … all confirmed accepted or dropped-but-stored in `recheck/probe-adv.mjs`). Recommendation: **`APPEND_USER_FILTER` first refuses any line with a leading/trailing `\p{White_Space}` or `\p{Cc}` character or an interior `\p{Cc}`/U+0085/U+2028/U+2029, then permits ONLY the two shapes the picker emits (a cosmetic hide and a scoped network block, defined in `SW1`) and refuses everything else by construction.** The options-page textarea keeps full syntax through `SET_USER_FILTERS` (extension-page only, unaffected). Residual (recorded, not fixed): a compromised renderer can still append any shape the picker legitimately produces, e.g. a generic `##div` hide — refusing that would remove the picker's legitimate generic-rule option, so it stays a residual (§4).

### Must-verify-before-planning items

**1. The network-rule path end to end — CONFIRMED WORKS on WASM, with two important caveats.**
`||ads.example/banner.png^` → `APPEND_USER_FILTER` → `appendUserFilterLine` → `_applyUserFiltersNow` → `compile_user_filters` (Rust `parse_network_rule_to_dnr`) → one dynamic DNR block rule (`probe-append.mjs`). Options that survive on the **WASM path**: `$image`→`resourceTypes:["image"]`, `$subdocument`→`sub_frame`, `$media`→`media`, `$domain=`→`initiatorDomains`, `$3p`→`domainType:"thirdParty"` — all verified emitting the correct DNR condition.
- **Caveat A (confirmed, load-bearing): `savePickerRule` reports success for a dropped line.** `||example.org^$redirect=noopjs` returns `{ok:true, counts:{network:0, skippedNetwork:1, skippedRules:[{id:null, line:"…", reason:"unsupported option: redirect"}]}}`. `savePickerRule` checks only `res?.ok`, so it shows "✅ Rule saved." **The orchestrator's claim is true.** → `PK1`.
- **Caveat B (confirmed, load-bearing): a `$…,domain=` network rule is SILENTLY dropped on the WASM-down fallback.** `||cdn.ads.example/b.png^$image,domain=example.com` on the JS fallback path (`parseSimpleNetworkRule`) → `{ok:true, network:0, skippedNetwork:0, skippedRules:[]}` — dropped with **no diagnostic at all**, because the fallback loop discards a `null` from `parseSimpleNetworkRule` without recording it, and `droppedLines` is only populated on the WASM path. `PK1` cannot catch this (skippedNetwork is 0). → `SW2`.

**2. The procedural path end to end — CONFIRMED WORKS on both paths.** `example.com##div:has-text(Sponsored)` from a content sender compiles to `userCosmeticRules.domainSpecific["example.com"] = ["div:has-text(Sponsored)"]` on both the WASM and fallback paths (`probe-append.mjs`). `build_page_bundle([], ["div:has-text(Sponsored)"], [], 150)` returns a procedural plan `[{type:"css",selector:"div"},{type:"op",op:"has-text",arg:"Sponsored"}]` (`probe-proc.mjs`); `.x:upward(2)` → `[{css:.x},{op:upward,arg:2}]`; `div:has(> img.ad)` → plain CSS `div:has(> img.ad){…}` (native). The engine's `_applyOp` implements `upward`/`has-text`/`has`, and the SW's WASM-down `parseProceduralPlan`/`extractFirstOp` produce the same plan shape. A generated `:has-text()`/`:upward()`/`:has()` rule is therefore executed, not shipped as dead CSS.

**3. THE TRUST BOUNDARY — verified, two layers, each stops a different threat.**
- **The PAGE (controls DOM the picker reads: class names, attribute values, `textContent`, resource URLs) → picker-side escaping.** Existing CSS candidates are protected by `CSS.escape`. The new kinds are not CSS. A hostile page can seed: `textContent` = `Sponsored)(evil` (a `)` closes `:has-text()` early → a different rule) or `/.*/` (a leading `/` is the engine's regex form → matches every element, blanks the page — `recheck/probe-hastext.mjs`); a resource path `/ad$script` (a `$` becomes an option separator, verified via the Rust `split_pattern_and_options` behaviour); a resource **host** `x$important,domain=bank.example` or `*` (the WHATWG URL parser lets `$ * , = { }` survive into `URL.hostname` — `recheck/probe-host.mjs` — so the host is page-controlled too, **correcting my first draft which claimed the hostname could not hold `$`**); text or URLs containing `##`/`#@#`; an overlong argument. `PK2a`/`PK3` escape URLs (validate the host, truncate the path at the first metachar) and text (truncate at `(`/`)`/`#`, refuse leading `/`) so a page cannot make the picker emit anything but the block/hide the user pointed at.
- **The RENDERER (a compromised content script sending `APPEND_USER_FILTER` directly) → service-worker validation.** `APPEND_USER_FILTER` is `SENDER_ANY` (`MESSAGE_SENDER_POLICY`), reachable from any renderer, and today the handler enforces only: non-empty string, single line (no `\n`/`\r`), and `utf8ByteLength ≤ MAX_USER_FILTERS_BYTES`. It does **not** restrict rule type. Verified from a content-script sender (`recheck/probe-ledger.mjs`): `@@*$document` → **accepted**, writes an `allow` rule on `main_frame` globally; `@@||bank.example^` → accepted allow; `||example.org^$important` → accepted priority-4 block; `@@/^https?:/$document` → accepted regex allow. **Newline IS refused** (`a\nb` → `{error:"APPEND_USER_FILTER accepts a single line"}`), but the refusal is not a sufficient backstop, because a JS `trim()` in the handler/`appendUserFilterLine` does not agree with the Rust compiler's `trim()` about where the line begins: `"\u0085@@||bank.example^"` survives JS trim with the NEL intact and compiles to a live allow rule (`recheck/probe-cp.mjs`). This is a **pre-existing** renderer-reachable hole; `SW1`'s allowlist (which refuses edge control/whitespace *before* any shape test, so the gate and compiler cannot disagree about the line's start) is the fix. Because the picker runs *in* the renderer, `SW1` — not the picker's escaping — is what stops a compromised renderer; the picker's escaping stops a hostile *page* from tricking the *user*.

## §2 Concerns

Conventions: **red-first** = write the test, run it on HEAD, record the failing assertion, then fix; **fix-shape revert** = before the PR, undo only the fix hunk (by file copy, never git) and confirm the new tests go red again; **mutate each half** separately. ### PK1 — the save path reports a compiler-dropped rule instead of claiming success

**Owns exclusively:** `src/content/element-picker.js`, `src/content/element-picker.test.mjs`.
**Where today.** `savePickerRule` (after the `APPEND_USER_FILTER` round-trip): `if (!res?.ok) { showErrorInDialog(...); return; }` then unconditionally `applyRuleImmediately`, `showSuccessInDialog(dialog, rule)`, toast "✅ Rule saved". `res.counts.skippedNetwork` / `res.counts.skippedRules` are ignored.
**Behaviour change.** After the `!res?.ok` guard, add: **the appended line applied iff its own entry is not in `skippedRules`.** Because `appendUserFilterLine` re-applies the *whole* stored file, `counts.skippedNetwork`/`skippedRules` describe every line, not just the one just saved (verified — a pre-existing `$removeparam` line makes every later clean save report `skippedNetwork:1` for the unrelated line, `recheck/probe-attrib.mjs` case (1)). So the picker must decide on the appended line specifically: `const dropped = res.counts?.skippedRules?.find(s => s.line === rule.trim());` — if `dropped`, show `dropped.reason` (fall back to "This rule couldn't be applied") through `showErrorInDialog`, do **not** `showSuccessInDialog`, do **not** toast success; otherwise behave exactly as today. Keep the single append; display-only.
**Why `rule.trim()` is the exact key.** A dropped entry's `line` is the compiler's trimmed line (WASM `droppedLines[].line` = the Rust-trimmed `raw_line.trim()`; the SW's `appendUserFilterLine` stores `line.trim()`). For any line `SW1` admits there is no leading/trailing whitespace, so the JS `rule.trim()` and the stored/reported form coincide byte-for-byte; the reviewer's ledger drop entry `line:"||example.org^$redirect=noopjs"` matches the input verbatim (`recheck/probe-ledger.mjs`). `SW2` (below) additionally guarantees the appended line's own entry is always present, cap-exempt, so this `find` cannot miss it even past 20 earlier drops.
**Must not change:** the single-atomic-append contract (pinned by "picker save is a single atomic APPEND_USER_FILTER message"); the `{error}` surfacing (pinned by "an APPEND_USER_FILTER error response is surfaced…"); the footer-listener preservation (pinned by "showing an error keeps the footer buttons…").
**Red-first tests (`element-picker.test.mjs`) — written so neither can pass vacuously (each pins the *attribution*, not just the presence of a drop).**
- `PK1: an unrelated dropped line does NOT block a clean save` — save `rule = '##.ad-banner'`; stub reply `{ok:true, counts:{network:0, cosmetic:1, skippedNetwork:1, skippedRules:[{id:null, line:'||facebook.com^$removeparam=fbclid', reason:'unsupported option: removeparam'}]}}` (the drop is a *different* line). Assert `/Rule saved/` **is** shown. *Fails a naive `skippedNetwork>0` implementation* (which would wrongly show the error) — this is the test the first-draft stub could not express.

**Owns exclusively:** `src/background/service-worker.js`, new `tests/sw-harness/sw-picker-guard.test.mjs` (shared with `SW1`; `SW2` adds tests to the same file it now owns). (Serial after `SW1`.)
**Blast radius:** **High** (`service-worker.js`). **Second reviewer required.**
**Where today.** In `_applyUserFiltersNow`, the JS fallback branch (WASM unavailable) iterates every non-`!` line and does `const rule = parseSimpleNetworkRule(trimmed, id++); if (rule) newRules.push(rule);`. A `null` return — the shape a `$…,domain=` network line yields, because `parseSimpleNetworkRule` cannot express `$domain=` — is discarded with no record, so `droppedLines` stays empty and `skippedNetwork` counts it as neither applied nor skipped. Verified: `||cdn.ads.example/b.png^$image,domain=example.com` on the fallback → `{ok:true, network:0, skippedNetwork:0, skippedRules:[]}` (`recheck/probe-ledger.mjs`; also `$object` and `$image,3p` silently drop the same way). **Second gap (reviewer's REQUIRED 2):** `skippedRules` is capped at 20 by `counts.skippedRules = skipped.slice(0, 20)`, so when more than 20 earlier lines were dropped, the appended line's own entry is not in the reply — `skippedNetwork:26, skippedRules.length:20, contains the new line? false` (`recheck/probe-attrib.mjs` case (2)) — and `PK1`'s `find(s => s.line === rule.trim())` would miss it.
**Behaviour change (two parts).**
1. **Record fallback drops.** In the fallback loop, when a line is **not** cosmetic (does not contain `##`/`#@#`/`#?#`) and `parseSimpleNetworkRule` returns `null`, push a `droppedLines` entry `{line: trimmed, reason: 'unsupported by the fallback compiler (WASM unavailable)'}` so it rides the existing skip channel into `skippedNetwork`/`skippedRules` exactly as a WASM-path drop does. Do **not** widen `parseSimpleNetworkRule` to support `$domain=` (that is REMEDIATION-2026-09 §7.3's job).
2. **Cap-exempt the appended line's own entry.** `APPEND_USER_FILTER` knows which line was just appended. When building the reply, if that line has a drop entry in `skipped`, ensure it is present in `counts.skippedRules` even past the 20-entry cap — e.g. the `APPEND` handler passes the appended `line.trim()` down (or post-processes the reply) so the reported `skippedRules` is `[appendedEntry, ...others.slice(0, 19)]` when the appended line was dropped, `others.slice(0, 20)` otherwise. The cap still bounds total size. This makes `PK1`'s `find` exact regardless of how many earlier lines were dropped, and needs no dual path in the picker.
**Must not change:** the WASM-path `droppedLines` behaviour (pinned by the existing user-filter tests); cosmetic-only lines must not be reported as dropped network rules (guard on the `##`/`#@#`/`#?#` test); the applied-count arithmetic (`skippedNetworkTotal = newRules.length - appliedNetworkRules + droppedLines.length` already folds `droppedLines`, so `skippedNetwork` is unchanged by the cap-exemption — only *which* entries appear in the capped `skippedRules` list changes).
**Red-first tests (`tests/sw-harness/sw-picker-guard.test.mjs`).**
- `SW2: a domain-scoped network line dropped on the WASM-down path is reported` — no compile override (fallback path); `||cdn.ads.example/b.png^$image,domain=example.com` → `res.counts.skippedNetwork >= 1` and `skippedRules` contains an entry with `line` equal to the input. *Fails today (skippedNetwork 0).*
- `SW2: the appended line's drop entry survives the 20-entry cap` — seed `userFilters` with 25 already-dropped lines (e.g. 25 `||old{i}.example^$redirect=noopjs`, WASM path), then `APPEND` a 26th dropped line `||ads.example^$csp=x`; assert `res.counts.skippedRules.some(s => s.line === '||ads.example^$csp=x')` is `true` while `skippedRules.length <= 20`. *Fails today (`contains new line? false`, `recheck/probe-attrib.mjs` case (2)).*
- `SW2 (didn't re-break): a cosmetic line is not reported as a dropped network rule` — fallback path; `example.com##.ad` → `res.counts.skippedNetwork === 0`, `counts.cosmetic === 1`.
- `SW2 (didn't re-break): a plain block still applies on the fallback` — `||ads.example/b.png^` → `counts.network === 1`, `skippedNetwork === 0`.
**Flag:** none (reporting only; no API-cadence change). **Rollback:** revert. **Effort:** M. **Depends on:** `SW1` (serial on the file). Part 1 (record fallback drops) may be **deferred** per decision 7; **part 2 (cap-exemption) should land with `PK2b`** so `PK1`'s attribution is exact for any user, WASM-up or down.

## §4 Risks and open questions

1. **WASM-down network candidates (decisions 2 & 7).** A `$…,domain=` block is silently dropped when WASM is down and only becomes honest with `SW2`; even then it is *reported*, not *applied*. If `SW2` is deferred, a network candidate saved during the boot window reports success while doing nothing. **Recommendation:** land `SW2`; it is a bounded honesty fix on a path the picker's headline feature depends on.
2. **`getComputedStyle` for background-image (`PK2a`).** The test harness has no `getComputedStyle`, so background-image detection is only unit-testable through `el.style.backgroundImage`. **Recommendation:** implement `el.style.backgroundImage` first (tested) and add a `typeof getComputedStyle === 'function'` guarded computed-style fallback for the real browser (manually verified on a background-image ad site in the release gate).
3. **`:nth-of-type` fragility (`PK4`).** A positional path is brittle across redeploys — it is a *fallback* for structurally-anonymous elements, ranked below id/class/text candidates, not a default. **Recommendation:** ship as the lowest-ranked candidate; the procedural `:has-text()` candidate (`PK3`) is the durable answer for hashed-class sites.
4. **`looksHashed` false positives (`PK4`).** A legitimate class (`h1`, `col-md-6`, `ad-slot-300x250`, `MuiBox-root`) must not be penalised as hashed. **Recommendation:** use exactly the pinned rule (`/^[A-Za-z]+-([A-Za-z0-9]{6,})$/` with ≥ 2 digits in the suffix), de-rank never drop, and test all eight of the reviewer's cases (`PK4`). Verified in `scratchpad/picker/plan/` to split that list correctly.
5. **`SW1` over-refusal.** The allowlist must not refuse a legitimate picker line. **Recommendation:** the "didn't re-break" test pins every picker-legitimate shape (cosmetic hide, `:has-text`/`:upward`/`:has`, scoped block); a second reviewer confirms option-name matching is on *tokens* after the `$` (a path literally containing `important` must not trip it) and that the control/whitespace refusal runs before any shape test (the NEL bypass test pins this).
6. **`SW1`/picker vocabulary drift.** `SW1`'s network-option allowlist and `PK2a`'s emitted tail, and `SW1`'s cosmetic-operator allowlist (`has-text`/`upward`) and `PK3`'s emitted operators, must stay in step; a picker candidate the gate does not permit is refused for the user. **Recommendation:** the cross-group sequencing (§3) pins the order; the `SW1` "didn't re-break" test drives the exact strings `PK2a`/`PK3` emit, so a future widening on one side that is not mirrored fails that test.
7. **Bundle growth (§1.5).** ~2–2.5 KB minified on every page. **Recommendation:** measure each PR with `scratchpad/release3/wp-check.sh`; if the content bundle approaches a hard ceiling, `PK4`/`PK5` are the first to drop.
8. **Manual release-gate additions.** Verify on a real image ad (network candidate blocks on reload), a hashed-class site (`:has-text()` survives), and one `$redirect=` paste into the picker (expect the `PK1` drop message, not "saved"). YouTube/Gmail golden paths unchanged (the picker does not run there unless invoked).
9. **Pre-existing page-blanking gap (recorded, not fixed here).** `##body`/`##html`/`##*`/`##:root` ship as injected `display:none` CSS that blanks the page; the root guard (`cosmetic-engine.js` `_hideElement`/`isPageBlankingDeclaration`) covers only the observer and `:style()` paths, not injected generic/domain CSS (`recheck/probe-adv.mjs`). `SW1` refuses these from content scripts, but the same shape from a filter list or the options-page textarea still blanks the page. **Recommendation:** file for the next remediation cycle — extend the root guard to the injected-CSS path (High blast, `cosmetic-engine.js`), out of scope for a picker phase.
10. **Residual after `SW1` (recorded).** A compromised renderer can still append any shape the picker legitimately produces — a generic `##div` hide, a scoped block. Refusing those would remove the picker's own legitimate options. Accepted as a residual; the renderer is already inside the trust boundary for everything the picker can do.

## §5 Deliberately left out

- **Element zapper / one-shot hide** (REMEDIATION-2026-09 §7.7) — a separate feature from rule authoring; out of scope.
- **Widening `parseSimpleNetworkRule` to full `$domain=` parity** — that is REMEDIATION-2026-09 §7.3's follow-up; `SW2` only makes the existing fallback *honest*, it does not extend it.
- **Randomising the picker's `__adblock_picker_*` ids/classes** (REMEDIATION-2026-09 §9.9) — the picker UI is torn down on save/cancel and is user-invoked, so its markers are transient; `PK5` removes the *persistent* inline-style tell, which is the part that outlives the session. Randomising the transient dialog ids is cosmetic and deferred.
- **Persisting a picked network rule as a static/DNR-managed rule** rather than a dynamic user rule — the dynamic user-filter path is the existing, tested channel; changing it is a High-blast-radius SW architecture change out of scope here.
- **`:matches-attr`/`:xpath`/`:matches-css`/`:others`/`:remove-*` candidates** — unimplemented or fail-closed in the engine (C1a/C1b) and too niche for point-and-click; excluded by decision 3.
- **A shared `filter-escape.js` module** for the picker and SW to share escaping — the two layers stop different threats (page vs renderer) and share no code path; a cross-file seam would add coupling for no reuse. Each keeps its own local, tested helper. (`SW1`'s allowlist and `PK2a`/`PK3`'s escaping are kept in step by the cross-group sequencing and the `SW1` "didn't re-break" test driving the picker's exact emitted strings — §4 item 6 — not by shared code.)
- **Fixing the injected-CSS page-blank gap** (`##body`/`##html`/`##*` from list or options-page rules) — a High-blast-radius `cosmetic-engine.js` change to extend the root guard to injected generic/domain CSS (§4 item 9); `SW1` closes the picker/renderer channel, the list/options channel is deferred to the next remediation cycle.
