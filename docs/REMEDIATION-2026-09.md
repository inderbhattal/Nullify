#### A1 — §3.1 (release 1; PR "storage: reads that feed a write must not degrade to empty")

**Where today.** `storage.js:66-79` `getStorageBulk` resolves `{}` when `chrome.runtime.lastError` is set or `result` is `undefined` (`:72-75`); `getStorage` (`:82-84`) maps through it. Consumers that write what they read: `readStoredAllowlist` `:2915-2917` (→ `allowSite` `:2920-2938`, `disallowSite` `:2964-2979`), `addAllowlistDomains` `:2952`, `appendUserFilterLine` `:2787`, `refreshMemoryCache` `:1419-1456` (reconcile at `:1445-1456`), `restorePersistedStats` `:2212-2262` (write-back at `:2259-2262`), `UPDATE_SETTINGS` handler `:3974` (`current = getStorage(SETTINGS) || {}` then merged and written), `initializeDefaults` `:1701` (`existing` null ⇒ rewrites `ALLOWLIST=[]`, `rebuildAllowlistRules([])`, `USER_FILTERS=''`, stats `0`, `ENABLED_RULESETS` defaults) — and it is called from `ensureBackgroundSetup` `:1288` on **every** SW start, not only from `onInstalled`; `ensureBackgroundSetup`'s own bulk read `:1293-1299` (`USER_FILTERS`/`USER_FILTERS_APPLIED`, read-only decision).

**Behaviour change.**
1. `storage.js`: add `export class StorageReadError extends Error` (`name='StorageReadError'`, `code='READ_FAILED'`). `getStorageBulk(keys)` **rejects** with it when the callback runs with `chrome.runtime.lastError` set; it still resolves `{}` when the result is `undefined` *without* `lastError` (the 2026-07 §5.11 TypeError guard stays). `getStorage(key)` inherits the rejection. Add lenient variants for read-only consumers: `getStorageBulkOrEmpty(keys)` (→ `{}` on failure) and `getStorageOrDefault(key, fallback)`. Add `StorageKeys.FEATURE_FLAGS='featureFlags'` and `getFeatureFlag(name, defaultValue)` (lenient).
2. `readStoredAllowlist`, `allowSite`, `disallowSite`, `addAllowlistDomains`, `appendUserFilterLine`, `UPDATE_SETTINGS`: no change to their code except that the rejection now propagates. The dispatcher (`:3863-3870`) already converts a rejected handler into `{error: err.message}` and reports it; the op chains (`enqueueAllowlistOp`/`enqueueUserFilterOp`) must not swallow — verify that a rejected op leaves the chain usable for the next op (it does: the chain is `promise.then(fn, fn)`-style; the test below asserts it).
3. `refreshMemoryCache`: wrap the bulk read in `try/catch StorageReadError`. On failure: `reportError('refreshMemoryCache:storageRead', err)`, **skip** the normalization check and the DNR reconcile entirely (no `rebuildAllowlistState`, no `rebuildAllowlistMatcher` from an empty list — leave `cachedAllowlist` untouched), set `allowlistCacheTrusted = false` (module flag; `isHostnameAllowedCached` unchanged — the allowlist mutators already read storage fresh), leave `cachedGenericCss` etc. as they were, and return. The return happens **before** `domainRulesCache.clear()`/`syncYouTubeShieldRegistration()` at `:1476-1479`: the shield registration is deliberately not touched from an untrusted cache — on a cold worker `cachedAllowlist` is empty, so a sync would compute `excludeMatches: []` and `updateContentScripts` the persisted registration, re-injecting the shield into an allowlisted YouTube tab (bullseye #2/#4 regressed by a storage fault). The boot continues (`_criticalReady` still becomes true) — a page load on an allowlisted site during that SW life is filtered, which is the safe direction; a later wake retries the read.
4. `restorePersistedStats`: on `StorageReadError` → `reportError('restorePersistedStats:storageRead', err)`, leave `_statsRestoreDone = false`, and reset `_statsRestorePromise = null` so the next writer re-attempts the restore. `persistTabStats` (`:2268-2278`, which writes `snapshotStatsForSession()` straight through — the `Math.max` merge at `:2247` is on the *read* side only): `if (!_statsRestoreDone) { await ensureStatsRestored(); if (!_statsRestoreDone) return; }` — a persist from an un-restored state writes nothing. The `ensureStatsRestored` catch at `:2201-2206` marks done only for non-`StorageReadError` failures.
5. `initializeDefaults`: wrap the `SETTINGS` read; on `StorageReadError` → `reportError('initializeDefaults:storageRead', err)` and **return without writing** (both callers — `onInstalled` and `ensureBackgroundSetup` — continue; defaults are re-attempted on the next start). Only a read that succeeded and returned `null` writes defaults. Rethrowing here would abort privacy rules, rulesets and the alarm for that SW life at the `ensureBackgroundSetup` call site. Implementer note: `sw-loader.mjs:66-69` seeds `SETTINGS` in every harness test precisely to keep this door shut, which is why nothing caught it.

## §7 Findings raised during implementation (release 1)

Recorded here so the release-2 tracks pick them up; none blocks release 1.

**7.1 `$3p`/`$1p` as the first option never splits in the build parser — 415 corpus rules emitted dead.** Found by Track B while porting `splitPatternAndOptions` and measured by the B1 second reviewer. `OPTION_LIST_HEAD` in `scripts/build-rules.mjs` requires a letter as the first character of the option tail, so `||host^$3p`, `$1p` and `$~3p` are treated as part of the pattern and emitted as a `urlFilter` carrying the literal text `$3p`, which matches nothing. Corpus: 415 network lines (ubo-filters 273, ubo-unbreak 125, others 17); 56 are `@@` exceptions (39 in ubo-unbreak), so those sites are over-blocked today. **Fix (Track D, D1, release 2):** accept `~?[13]p` in the head rule (one character class), then re-measure the 28 `$1`/`$2` replacement-text tails the wider head could touch. The Rust user-filter compiler (B1 PR 2) handles `$3p`-first correctly and pins the build's current answer as an `expect.build` seam vector, so D1's fix is caught by `wasm-parity.test.mjs`. Severity: P1 (coverage loss, silent).

**7.2 Seam: D1 must edit `tests/fixtures/filter-vectors.mjs`, which Track B owns.** Twelve network vectors carry `expect.build = {emit, why}` pinning the build parser's current behaviour where it differs from the §3.3 table (`$to=`, `$from=`, `$denyallow=`, `$method=`, scoped `*`, `$all`, non-ASCII `$domain=`, `$redirect=`, literal `$removeparam=`, `$3p`-first). When D1 changes the build, those pins go stale and the parity test fails by design. D1's PR flips the pins in the same change; B reviews it. Ownership of the fixture file passes to D for that PR only.

**7.3 Runtime fallback (`parseSimpleNetworkRule`) is looser than the build on four shapes** — `||$script` (emits `urlFilter "||"`), `$SCRIPT`, `$script,Image`, `\$script`; none vectored. Track A, A2 (the SW owner): make the fallback at least as strict as the build on these and add them as vectors; `emit_runtime ⇒ emit_build` already holds on the current 35.

**7.4 A1 follow-ups deferred to A2** (from the A1 second review): a deduplicated `refreshMemoryCache()` retry in the critical-message gate when the allowlist cache is untrusted; a `getEffectiveEnabledRulesetsMap()` fallback for the index rebuild's lenient read; a local catch in `applyRulesets` instead of a fatal critical; options page disables Save when `GET_USER_FILTERS` answers `{error}` (Track H owns `options.js`).

**7.5 A1b follow-ups:** the SW's `*` universal-selector predecessor rule still skips whitespace where Rust uses the immediate predecessor (§4.35 of 2026-08); the SW's `extractFirstOp` does not port the engine's nested-native scan or `MALFORMED` fail-closed shape. Both JS-path only; A2.

**7.6 B1 compiler follow-ups:** `*$all` in a user filter is a browser-wide block as written (uBO does the same; consider requiring domain scoping for the empty-pattern form); three seam pins are permanent rather than dated; `:others()` re-walks the document once per rule per procedural run (C-track: a per-run shared `querySelectorAll('*')` snapshot if profiles show it).

**7.7 The build parser has the same three fail-open shapes the B1 second review found in Rust** (`scripts/build-rules.mjs` `parseOptions`, Track D, D1): (a) `$~domain=x` is treated as un-negated, scoping the rule to x instead of excluding it; (b) an entry that is exactly `~` (`$domain=~`) ships as an empty-string domain that Chrome rejects at index time, losing the whole rule silently; (c) `$script,~script` emits both `resourceTypes` and `excludedResourceTypes` with the same member, which Chrome also rejects. The Rust compiler now refuses all three (e4927b3) and the corresponding vectors pin the build's current answers; D1 mirrors the refusals and flips the pins. Re-measure the corpus for each shape in the D1 PR. Severity: P2 (rules lost, not broadened) except (a), which is P1 if any corpus rule uses a negated key.

**7.8 `wrapInstanceGetter` accessors carry an own `prototype` (release-2 F1 second review).** `src/scriptlets/shared-utils.js` `wrapInstanceGetter` builds the replacement accessor with a function expression, which has `[[Construct]]` and therefore an own `prototype` property; native getters have neither, so `Object.getOwnPropertyNames(Object.getOwnPropertyDescriptor(XMLHttpRequest.prototype, 'responseText').get)` distinguishes a wrapped getter. Same leak class in `bot-stealth.js:50-63` and `spoof-css.js:60-79` (plain function expressions passed to `maskNative`). `proxyApply` and `maskNative`'s Proxy paths are clean. **Fix (release 3, one PR):** build the accessor with method syntax (`({ get() { … } }).get`), which has no `prototype`; convert the two scriptlet sites the same way; add a detector test asserting no own `prototype` on any wrapped accessor. Consumers affected: json-prune, m3u-prune, trusted-replace-fetch-response, spoof-css, youtube-shield. Ownership: shared-utils.js and the scriptlets are untouched-by-design in this plan; assign to Track F (F3 already touches bot-stealth.js) with shared-utils.js added to F's ownership for that PR. Severity: P2 (detectability only).
