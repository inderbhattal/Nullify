## 1. Executive Summary

Nullify at 4.1.0 has closed most of the *lifecycle* debt the May review identified. The YouTube shield race (prior 3.4), the in-flight bundle cache poisoning (3.5), the WASM null-guards (3.2), the ruleset-priority validation (6.3), the user-filter size cap (6.4), the swallowed scriptlet errors (6.1) and the `contextMenus` `lastError` gap (6.2) are all genuinely fixed, several with regression tests. The `tests/sw-harness/` YouTube suite is a real asset and directly addresses the "regression treadmill" thesis in `docs/IMPLEMENTATION.md`.

The problem is that the debt moved. This pass found seven ship-blockers, and they share one shape: **a feature is silently dead in the shipping configuration while every observable signal says it is working.** In each case the failure is masked — by a swallowed exception, by a partially-working fallback, by a dev-only code path that behaves differently from the packed build, or by a count that keeps incrementing off a different code path.

The headline items:

1. **All procedural cosmetic filtering is dead whenever WASM is healthy** (§3.1). A `Uint8Array` is passed through `chrome.runtime` messaging, which JSON-serializes it; the content script throws on decode and the error is swallowed by a bare `.catch(() => {})`. Plain CSS hiding still works, which hides the breakage.
2. **39% of shipped scriptlet rules (5,213 / 13,330) resolve to no implementation** (§3.6), and roughly 2,400 of those are aliases of scriptlets that already exist — a one-line registry fix each.
3. **`$ghide`/`$ehide`/`$shide` exceptions compile to blanket network-allow rules** (§3.3), turning "don't apply generic cosmetics here" into "disable ad blocking here".
4. **Unknown filter modifiers are stripped and the broadened rule ships anyway** (§3.4) — `$badfilter` becomes an active block, bare `$removeparam` becomes a full domain block.
5. **The malware ruleset cannot block navigations** (§3.5): all 5,888 rules omit `resourceTypes`, and DNR excludes `main_frame` by default.
6. **`patternToRegex` returns a `g`-flagged regex used with `.test()`** (§3.2), so `prevent-fetch`/`prevent-xhr` block every *other* matching request.
7. **One line of page script disables every scriptlet on that page** (§3.7) via `JSON.stringify` capture.

Beneath the P0s sit two systemic issues worth naming separately, because they each produce findings in three or four different files:

- **Parser drift between the three filter parsers.** `wasm-core/src/lib.rs`, `src/shared/filter-parser.js`, and `scripts/build-rules.mjs` each independently parse ABP syntax, and they disagree. `~domain` negation is dropped by all three (§4.3); `#@#+js()` scriptlet exceptions are misparsed differently by each (§4.4); `$important` priority is inverted in two of them (§4.10). Every divergence is a silent behavior change, and the JS fallback path can resurrect rules the Rust path deliberately dropped (§5.14).
- **Failure paths that report success.** `applyUserFilters` records "applied" after a failed DNR write (§4.6); the options UI never checks for the `{error: …}` response shape (§4.16); the allowlist import replaces state off a read that degrades to `[]` (§4.17); "Update All" prints a fresh timestamp for an update that did nothing (§5.29).

The security posture of the UI remains good — `sender.id` is enforced, allowlist input is normalized through `URL`/PSL, no telemetry, no `eval`. The exceptions are one unescaped `innerHTML` interpolation in the logger (§4.13) and the still-missing privilege gate on destructive message handlers (prior 2.3, still open).

**Recommended gate before any further feature work:** §3 in full. Items §3.1, §3.2, §3.6 and §3.7 are each a small, well-scoped patch with large user-visible impact.

## 3. P0 — Ship Blockers

### 3.1 All procedural cosmetic filtering is silently dead on the primary path **[verified]** **[FIXED]**

**Where:** `src/background/service-worker.js:2711-2714`, `src/content/content-main.js:56-58, 120-122, 160`

The service worker attaches a `Uint8Array` to the message response and deletes the JSON fallback:

```js
if (wasmReady && !isAllowed && cosmeticBundle.cosmeticRulesBinary) {
  try {
    responseData.cosmeticRulesBinary = cosmeticBundle.cosmeticRulesBinary;
    delete responseData.cosmeticRules;
```

`chrome.runtime` messaging JSON-serializes its payload. A `Uint8Array` arrives in the content script as a plain object (`{"0":…,"1":…}`), never a typed array. The consumer:

```js
function decodeBinaryRules(buffer) {
  const rules = { generic: [], domainSpecific: [], exceptions: [] };
  const view = new DataView(buffer.buffer, buffer.byteOffset, buffer.byteLength);
```

`buffer.buffer` is `undefined` → `new DataView(undefined, …)` throws `TypeError` → the rejection is swallowed by `main().catch(() => {})` at `content-main.js:160`.

**Failure scenario:** any page load on the normal warm path (WASM initialized, site not allowlisted). `main()` dies at line 121. `CosmeticEngine` is never constructed, so every procedural rule (`:has-text`, `:upward`, `:remove`, `:matches-attr`, …), every `genericProceduralRule`, and every engine-level exception is dead — on every page, for every user. Static `cssText`/`exceptionCss` are injected at lines 116-117, *before* the throw, so basic hiding still works and the regression is invisible. The JSON fallback path only runs when WASM has failed, so the feature works exactly when the extension is unhealthy.

Two independent reviewers found this separately; it is the single highest-impact defect in the codebase.

**Fix:**
1. Transport-encode: `responseData.cosmeticRulesBinary = Array.from(bundle.cosmeticRulesBinary)` (or base64), rehydrate content-side with `new Uint8Array(arr)` before `decodeBinaryRules`.
2. Stop deleting `responseData.cosmeticRules` — keep the JSON fallback as a safety net.
3. Wrap `decodeBinaryRules` in try/catch that falls back to `cosmeticRules`.
4. Replace `main().catch(() => {})` with a `reportError` call. A bare swallow on the entry point is what made this invisible for a release cycle.
5. **Test:** round-trip a bundle through `JSON.parse(JSON.stringify(response))` before asserting the decode. Note that an in-memory chrome stub passes objects by reference and will *not* catch this — the test must serialize explicitly.

### 3.2 `patternToRegex` returns a `g`-flagged regex reused with `.test()` — every second matching request is allowed **[verified]** **[FIXED]**

**Where:** `src/scriptlets/shared-utils.js:21`; consumers `prevent-fetch.js:10,16`, `prevent-xhr.js:10,19`, `hide-window-error.js:15,20,35`

```js
return new RegExp(pattern.replace(/[.*+?^${}()|[\]\\]/g, '\\$&'), 'g');
```

`RegExp.prototype.test` on a `g` regex reads and advances `lastIndex`. Consumers build the regex once and reuse it across calls. Reproduced with the shipped pattern `doubleclick`:

```
call 0 -> true   lastIndex 22
call 1 -> false  lastIndex 0      <-- request allowed through
call 2 -> true   lastIndex 22
call 3 -> false  lastIndex 0
```

**Failure scenario:** a page fetching the same ad/analytics endpoint more than once (retry, SPA re-navigation, multiple ad slots) is blocked on odd calls and allowed on even ones. 544 shipped `no-fetch-if`/`no-xhr-if`/`prevent-*` rules use plain-string patterns and therefore run at roughly half effectiveness. `hide-window-error` alternates hiding and printing the same error.

**Fix:** drop the `g` flag from the escaping branch of `patternToRegex` — it is only ever used with `.test()`. Keep `g` in `toRegex`, which feeds `String.replace`; the two use cases need separate helpers. Defensively set `re.lastIndex = 0` before each `.test()` in the three consumers.

### 3.3 `$ghide`/`$ehide`/`$shide` exceptions compile to blanket network-allow rules **[verified]** **[FIXED]**

**Where:** `scripts/build-rules.mjs:491-497`, `:398`, `:498`

Only the long-form names are recognized:

```js
} else if (['genericblock', 'generichide', 'elemhide', 'specifichide'].includes(optName)) {
```

Unknown options are silently ignored (`:498`), so the short aliases fall through to `networkFilterToDNR` and emit an `allow` at priority 3 — above every block (1) and every `$important` block (2). Executed against the shipped parser:

```
@@||example.com^$generichide -> {"type":"cosmetic-scope-exception","scopes":["generichide"]}   ✅ correct
@@||example.com^$ghide       -> {"priority":3,"action":{"type":"allow"},"condition":{"urlFilter":"||example.com^"}}   ❌
@@||example.com^$shide       -> same ❌
@@||example.com^$csp         -> same ❌  (exceptions are exempted from the csp skip at :398)
```

**Failure scenario:** uAssets `unbreak.txt` ships a whole `$ghide` section. `@@||che168.com^$ghide` means "don't apply generic cosmetics on che168.com, keep network blocking". Nullify instead allows *every network request* to that domain at the highest non-system priority — ads and trackers fully unblocked, silently. Corroborating evidence in the artifacts: `rules/ubo-unbreak.json` holds 361 allow rules with no `resourceTypes`, consistent with converted `$ghide` lines, while `cosmetic-rules.json:genericExcludedDomains` captured only 163 domains from the long-form tokens.

**Fix:** add `ghide`, `ehide`, `shide` (and `gblock`) to the cosmetic-scope branch; route `@@…$csp` to `skip()`. Structurally: an exception rule carrying *only* non-network modifiers must never emit a network rule.

### 3.4 Unknown modifiers are stripped and the broadened rule ships **[verified]** **[FIXED]**

**Where:** `scripts/build-rules.mjs:498` (`// Ignore unknown options silently`), `:483`

Executed against the shipped parser:

| Filter line | Emitted DNR rule | Correct behavior |
|---|---|---|
| `\|\|example.com^$badfilter` | `{action: block}` | cancel a matching rule |
| `\|\|example.com^$removeparam` | `{action: block}` | strip all query params |
| `\|\|example.com^$script,denyallow=cdn.example,domain=site.example` | block, **no** `excludedRequestDomains` | allow cdn.example |
| `\|\|example.com^$header=…` / `$method=post` | unconditional block | conditional block |

**Failure scenario:** `$badfilter` inverts — a line whose entire purpose is to *cancel* a filter instates it instead. `$badfilter` is live in the fetched lists (see `||thegay.com^$csp=...,badfilter` in `rules/skipped/ubo-filters.log`). A bare `$removeparam` — a parameter-hygiene rule — becomes a hard block of the whole domain. `$denyallow` drops the exclusion, so the CDN the filter author explicitly protected is blocked and the site breaks.

**Fix:** invert the default. Maintain an explicit allowlist of *ignorable* options; any unrecognized semantic option must `skip()` the entire rule (fail closed) and increment the existing unsupported-option drop counter. Then implement `$badfilter` as a two-pass suppression per prior review 4.1.

### 3.5 The malware ruleset cannot block navigations — all 5,888 rules omit `main_frame` **[verified]** **[FIXED]**

**Where:** `scripts/build-rules.mjs:774-776`

```js
if (options.resourceTypes.length > 0) {
  condition.resourceTypes = options.resourceTypes;
}
```

Chrome DNR: a condition **without** `resourceTypes` matches every type *except* `main_frame`. Verified against the artifact — 5,888 of 5,888 rules in `rules/malware.json` have no `resourceTypes`:

```json
{"id":118759,"priority":1,"condition":{"urlFilter":"0011.s3.cubbit.eu"},"action":{"type":"block"}}
```

**Failure scenario:** the user clicks a link to a listed malicious host. The main-frame request matches no rule and the page loads. The URLhaus list's entire purpose is stopping navigation to malicious URLs; only subresources are blocked. Compounding this, upstream's `$all`/`$doc` modifiers — which exist precisely to include documents — are among the silently-discarded unknowns from §3.4.

**Fix:** for hostname-block security lists, emit `resourceTypes` including `main_frame` (uBO Lite does this for its badware sets). Implement `$all`/`$doc` → the full resource-type set. Add a build-time assertion that `malware.json` contains at least one `main_frame` rule.

### 3.7 One line of page script disables every scriptlet on the page **[verified]** **[FIXED]**

**Where:** `src/scriptlets/index.js:148-165`

```js
function run(name, args = []) {
  const fn = REGISTRY.get(name);
  if (!fn) return;
  const key = `${name}|${JSON.stringify(args)}`;   // page-controlled, outside the try
  if (executed.has(key)) return;
  executed.add(key);
  try { fn(...args); } catch { }
}
```

**Failure scenario A:** the page ships `<script>JSON.stringify=()=>{throw 0}</script>`. Every `run()` throws before reaching its try; the throw is swallowed by the per-spec `catch {}` in `executeScriptlets` (`service-worker.js:2621-2625`); **all** scriptlets are skipped on that page with no error and no counter.
**Failure scenario B:** `JSON.stringify = () => ''` collapses every dedupe key to the same value, so only the first scriptlet in the list ever runs.

**Fix:** capture the primitive at bundle load (`const stringify = JSON.stringify` at module top) — better still, avoid JSON entirely: `name + '|' + args.length + '|' + args.join(' ')`. Move key computation inside the try.

### 3.8 `trusted-replace-*-response` and `m3u-prune` have inverted argument order — all 24 shipped rules are no-ops

**Where:** `src/scriptlets/trusted-replace-fetch-response.js:31,34,39`; `m3u-prune.js:13`

```js
export function trustedReplaceFetchResponse(urlPattern, findStr, replaceStr = '') {
  const matchUrl = toMatcher(urlPattern);
```

uBO's signature is `(pattern, replacement, propsToMatch)` — argument 1 is the *body* pattern, argument 3 is the URL matcher. The shipped rules confirm uBO ordering:

```json
{"name":"trusted-replace-fetch-response","args":["adPlacements","no_ads","player?"]}
{"name":"m3u-prune","args":["lura.live/prod/","/prog.m3u8"]}
```

**Failure scenario:** the YouTube rule evaluates `matchUrl('adPlacements')` → `url.includes('adPlacements')` → no YouTube URL contains that string → the interceptor never fires and `adPlacements` is never stripped. Worse, if a URL *did* match, the scriptlet would search the body for `"no_ads"` and delete it, corrupting the payload. `m3u-prune` has the same swap: it matches playlist URLs against the ad-segment pattern and prunes lines matching the URL pattern.

**Fix:** re-order to uBO's signature — `(pattern, replacement, propsToMatch)` for both replace scriptlets, `(m3uPattern, urlPattern)` for `m3u-prune` — and treat an empty `propsToMatch` as match-all. Add a fixture test that feeds the literal shipped args through the registry and asserts interception.

## 4. P1 — Correctness

### 4.1 Bloom filter hash functions differ between JS and WASM; cross-loading kills ~99% of domain-specific cosmetics **[verified]**

**Where:** `src/shared/bloom.js:63-70` vs `wasm-core/src/lib.rs:82-89`; trigger at `src/background/service-worker.js:1259-1261`

JS is a 32-bit FNV-1a variant; Rust is 64-bit with the FNV-64 prime:

```js
let hash = 0x811c9dc5 ^ seed;
hash ^= key.charCodeAt(i);
hash += (hash << 1) + (hash << 4) + (hash << 7) + (hash << 8) + (hash << 24);
```
```rust
let mut h = 0x811c9dc5u64 ^ (seed as u64);
h ^= *b as u64;
h = h.wrapping_mul(0x100000001b3);
```

Yet the service worker feeds a JS-serialized filter straight into the WASM deserializer:

```js
if (wasmReady) {
  bloom = WasmBloom.deserialize_from_json(JSON.stringify(data));
```

The serialized shape matches `SerializedBloom` and passes length validation, so it loads "successfully" while every non-empty key maps to different bits. Simulated with 2,000 hostnames: **1,999/2,000 false negatives**; `"example.com"` maps to `[60198, 41457, 105056, 128235]` under JS and `[103398, 130129, 127840, 5643]` under Rust.

**Failure scenario:** session A runs with `wasmReady === false` (WASM fetch failed, or a rebuild raced ahead of init) and persists a JS-built filter. Session B boots with WASM ready and cross-loads it. `bloom.has(d)` gates every domain-specific cosmetic DB lookup (`service-worker.js:2942`) and now returns false for ~99% of domains. The `""` sentinel hashes identically in both (no bytes processed), so `check_hostname`'s short-circuit keeps scriptlets alive and masks the breakage. Fill-ratio monitoring does not catch it — the set-bit count is unchanged.

**Fix:** make the hashes bit-identical (port the 32-bit FNV-1a to Rust; UTF-8 bytes equal UTF-16 code units for ASCII hostnames). Add a `hashAlgo`/`format` field to both serializers and rebuild rather than cross-load on mismatch. Add a cross-engine golden test: fixed key → fixed bit indices, asserted on both sides.

### 4.2 Bloom size arithmetic overflows on wasm32, re-opening the panic 8045c14 closed **[verified]**

**Where:** `wasm-core/src/lib.rs:53-55`, `:110-123`; `wasm-core/Cargo.toml` (`[profile.release]` sets no `overflow-checks`)

```rust
let bitset_size = (size + 31) / 32;
...
Ok(s) if s.size > 0 && s.hashes > 0 && s.data.len() == (s.size + 31) / 32 =>
```

On wasm32 `usize` is 32-bit and release builds wrap. The payload `{"size":4294967295,"hashes":1,"data":[]}` computes `(4294967295 + 31)/32` → wraps to `0`, `data.len() == 0` passes, the filter is accepted — and the first `has()` indexes an empty `Vec` out of bounds. With `panic = "abort"` the instance is poisoned, and this happens on the request hot path (`service-worker.js:3011`), *after* the load-time try/catch. Reachable from corrupt or hostile `chrome.storage` contents — exactly the threat model commit 8045c14 addressed.

**Fix:**
```rust
const MAX_BLOOM_BITS: usize = 1 << 27; // 128 Mbit, far above real use
let size = size.clamp(1, MAX_BLOOM_BITS);
let bitset_size = size / 32 + 1;       // cannot overflow
// deserialize: reject s.size > MAX_BLOOM_BITS before the length check
```
Mirror the validation in `bloom.js:56-60`, which today has none — a truncated `data` array loads silently and yields false negatives (over-length throws `RangeError` and is at least caught).

### 4.3 `~domain` negation is dropped by all three parsers **[verified]** **[FIXED in JS; wasm-core open]**

**Where:** `src/shared/filter-parser.js:135, 149, 162, 175`; `wasm-core/src/lib.rs:648-654`; `scripts/build-rules.mjs` (same class)

```js
domains: domains ? domains.split(',').map(d => d.trim()).filter(Boolean) : []
```

### 4.14 `db.js` has no `transaction.onabort` handler anywhere — commit-time aborts hang every wrapper promise

```js

```

Per the IndexedDB spec, a transaction that aborts without a failed *request* — quota exceeded at commit, forced close under storage pressure, internal IO error — fires only `abort` on the transaction, not `error`. With no `onabort`, the promise never settles.

**Failure scenario:** the bundle registers its dispatcher under the forged key, so `executeScriptlets(SCRIPTLET_REGISTRY_KEY, specs)` finds nothing and returns. Every scriptlet is dropped. On the next injection `hasScriptletRegistry` is false → re-seed → `defineProperty` now throws against the page's non-configurable property → `seeded === false` → skip. The page has permanently disabled scriptlets for itself. A variant pre-claims the real key with `{value:{run:spy}, configurable:false}`; `index.js` swallows the resulting throw at `:187-189` and the SW then hands the page's spy the full rule list for that site.

2. When `defineProperty` throws in the bundle, do not leave the page's object in place; stamp a private token the SW verifies before passing specs.
3. Real fix: eliminate the gap with `chrome.scripting.registerContentScripts({ world: 'MAIN', runAt: 'document_start' })` for the bundle, so it runs before any page script. This also closes §5.20.

### 4.31 `patternToRegex` and friends treat any path-like `/a/b` argument as `/regex/flags`

### 4.33 `json-prune` lacks `[]`/`*` wildcards; `remove-attr`/`add-class`/`remove-class` don't split `|` token lists **[verified]**

**Where:** `json-prune.js:57-85`; `remove-attr.js:2-4`, `add-class.js:4`, `remove-class.js:4`

## 5. P2 — Hardening

Grouped by area. Each is a real defect with a concrete trigger, but with narrower blast radius than the above.

### Service worker

**5.1 `performEarlyInjection` checks the allowlist before caches restore** (`service-worker.js:3050-3060`). On a cold start the navigation that wakes the SW sees an empty `cachedAllowlist`, so `isHostnameAllowedCached` returns false and cosmetic CSS is injected into an allowlisted page via `insertCSS` — with nothing to remove it, since the content script sees `isAllowed` and returns early. Fix: await `_criticalPromise` at the top and re-check after the bundle await.

**5.2 `restorePersistedStats` races `resetTabStats`** (`:1796-1825` vs `:3097-3099`). The navigation that wakes the SW resets tab stats; stage-2 restore then clears the map and reloads the *previous* session's counts, so the badge shows the prior page's count plus new blocks. Fix: restore only tabIds not already present in memory.

**5.3 Active-index rebuild has no mutual exclusion** (`:861-955`, entered from four call sites, only one debounced). A navigation during a rebuild can persist a bundle built against cleared stores, landing *after* the rebuild's final `clearPageBundles()`. Because `activeRuleDataVersion` doesn't change on remote-list refresh, the version check accepts the poisoned record and that hostname serves an empty bundle indefinitely. Fix: route all rebuilds through one in-flight chain and skip `putPageBundle` while a rebuild is in flight.

**5.4 `GET_TAB_STATS` accepts an arbitrary `tabId` from any sender** (`:2730-2733`), returning `{blocked, trackers, url}`. A compromised renderer can enumerate tabIds and read every open tab's URL. Fix: honor `payload.tabId` only when `sender.tab` is absent and `sender.url` is an extension page.

**5.5 `RUN_SCRIPTLETS`/`GET_SCRIPTLET_RULES` ignore the allowlist and accept arbitrary scriptlet names and args** (`:2803-2816`), unlike `GET_INIT_DATA` which gates on `!isAllowed`. Neither has any caller in `src/content/`, `src/popup/`, or `src/options/` — dead but reachable attack surface. Fix: delete them, or gate on the allowlist and restrict to a name allowlist.

**5.6 Unhandled rejections in webNavigation listeners** (`:3101-3104`, `:3110-3112`). A persistent IndexedDB failure emits an unhandled rejection per navigation, and nothing reaches `errorReport` — so `GET_ERROR_REPORT` shows a healthy extension while cosmetic pre-warm is dead. Fix: try/catch routing to `reportError('webNavigation', err)`.

**5.7 Drifted duplicate tables** (`:54-57` vs `:161-162`; `:2364-2367` vs `:106-109`). `CONFIG.DOMAIN_RULES_CACHE_MAX`/`PAGE_BUNDLE_DB_MAX` are dead (the live values are separate consts); `CONFIG.PROCEDURAL_DEBOUNCE_MS`/`CACHE_SWEEP_INTERVAL_MS` are referenced nowhere. `applyRulesets` re-declares `allKnownListIds` as a literal that must stay in sync with `ALL_KNOWN_LIST_IDS` — adding a list updates the latter automatically but not the former, so the new ruleset would never be enabled. Fix: single source of truth for each.

**5.8 Three allowlist matchers with different semantics** — the WASM `AllowlistMatcher`, the `isHostnameAllowedCached` fallback walk (`:3036-3043`, which has *no* PSL stop), and the dead exported `isHostnameAllowed` in `storage.js:75-86`. With a `co.uk` entry stored, the WASM path returns false and the fallback returns true — the same input blankets a TLD only when WASM is down. Fix: one shared helper built on `ancestorDomains`; delete the dead one.

**5.9 Stats debounce loses data on SW kill** (prior 3.3, unchanged at `:1827-1834`). Fix as originally proposed: `chrome.storage.session` for in-flight counters.

**5.10 Filter-list fetch has no timeout or size cap** (prior 2.6, unchanged at `filter-parser.js:217-221`). Fix: `AbortController` + a ~25 MB stream cap + last-known-good fallback.

### Shared libraries

**5.11 `getStorageBulk` ignores `chrome.runtime.lastError`** (`storage.js:42-53`). On a failed read Chrome invokes the callback with `undefined`; `getStorage` then does `(undefined)[key]` and throws `TypeError` into callers written against a "returns null" contract.

**5.12 Concurrent `db.open()` creates two connections and the `versionchange` handler closes the wrong one** (`db.js:24-27, 60-70`). The handler closes `this.db` (the *current* connection) rather than its own, so an extension update closes the active connection — subsequent transactions throw `InvalidStateError` — while the leaked one keeps blocking the upgrade. Fix: cache the in-flight promise; bind the handler to its own connection object.

**5.13 `fetchAndExpand`'s `!#if` heuristic includes negated sections** **[FIXED]** (`filter-parser.js:230-235`, and the same bug in `build-rules.mjs:193-198`). `!#if !env_chromium` *contains* `env_chromium` → evaluates true → Firefox-only sections are included on Chrome; `!#if !env_mobile` evaluates false → desktop-applicable filters are excluded. Both forms occur in uAssets. A stray `!#else` on an empty stack silently drops the remainder of the list (`!#endif` has a guard; `!#else` doesn't). Fix: tokenize and evaluate `!`/`&&`/`||` against a defined-symbol set.

**5.14 The JS fallback resurrects rules the Rust compiler deliberately dropped** (`service-worker.js:2029-2037`). `parseSimpleNetworkRule` has neither the critical-path guard nor `$badfilter` handling, and it runs whenever `newRules.length === 0`. A user filter of exactly `||googlevideo.com/videoplayback` is correctly dropped by the guard, then re-emitted by the fallback — breaking YouTube playback, the precise outcome the guard exists to prevent. Fix: distinguish "WASM succeeded with zero rules" from "WASM failed".

**5.15 Cosmetic lookups are not snapshot-consistent** (prior 5.2, half fixed). `getScriptletRules` now uses one transaction, but `getCosmeticRules` opens one per ancestor domain, so a concurrent rebuild yields a bundle mixing pre- and post-clear state — which is then persisted.

**5.16 No `chrome.storage.local` quota handling** (prior 5.1, still open). No `QUOTA_BYTES` detection anywhere, no `unlimitedStorage` permission, no user surfacing. Combined with §4.14 an IndexedDB quota failure now *hangs* rather than rejecting.

### WASM core

**5.17 `parse_scriptlet_args` deletes quote characters from argument interiors** (`lib.rs:685-715`), diverging from the JS parser which preserves them. `div[id='ad']` becomes `div[id=ad]`; an unpaired apostrophe leaves the quote state open so subsequent commas stop splitting and arguments merge.

**5.18 Procedural exceptions can't suppress procedural rules** (`lib.rs:1590-1608`). `is_css_safe_selector` rejects any selector containing a procedural operator, so a `#@#` exception for `div:has-text(Ad)` is discarded before the suppression check ever runs.

**5.19 Binary rule framing has no escaping** (`lib.rs:1564-1582`). Entries are NUL-terminated and `is_valid_selector` doesn't reject `U+0000`, so a corrupt list line with an interior NUL desyncs the decoder and shifts every subsequent exception. Fix: reject `\0` in `is_valid_selector` (one character in an existing check) or length-prefix.

**5.20 No input-size caps** (prior 9.2, still open) — `compile_user_filters`, `parse_filter_source`, `process_youtube_player`, `compile_active_filter_index` all accept unbounded input, and WASM linear memory never shrinks.

**5.21 Plan JSON is still unversioned** (prior 9.3, still open), and the `from_js_value` structs lack `#[serde(default)]`, so a stored bundle missing one field hard-fails the whole compile and silently reverts to the slower JS merge path.

**5.22 Quadratic allocation in `has_invalid_universal_usage`** (`lib.rs:1395`, `:1480`) — a `Vec<char>` per selector plus a whole-tail `String` per `::` occurrence, across ~45k selectors on every index rebuild. Fix: iterate `char_indices()` and compare with `starts_with` on the original `&str`.

**5.23 `UrlSanitizer::sanitize` drops the URL fragment and matches keys by substring** (`lib.rs:1085-1101`) — `ref` also strips `referral_code`. Currently latent (no content script reads `sanitizedUrl`); fix before it grows a consumer.

### Content scripts

**5.24 `:semantic()` verdict cache leaks and can type-confuse the shared op cache** (`cosmetic-engine.js:647-662`). Boolean verdicts are stored in the same Map that holds `op|arg → WeakMap` entries, are never registered in `_cacheAccessOrder` (so eviction can't reach them), and an element whose text prefix equals the operator argument overwrites the WeakMap with `true` — the next `opCache.has(el)` throws.

**5.25 Dirty-roots overflow discards invalidation data** (`:773-779`). The forced run executes against the *previous* snapshot, then clears the dirty set — so a hydration burst that inserts a "Sponsored" label into a previously-cached container leaves it visible for the page's life. It also bypasses the debounce, running a full document scan synchronously inside the observer callback.

**5.26 Op-first plans seed `document.documentElement`** (`:362-364`). A user filter of `##:has-text(Sponsored)` — a natural first attempt — matches the root element on any page containing that word and applies `display:none` to `<html>`. Fix: reject op-first plans with no base selector, or expand the candidate set.

**5.27 Hidden/removed counters inflate in background tabs** (`:836-849`, `:866-885`). Dedupe depends on an attribute set inside a `requestAnimationFrame` flush, which doesn't run in hidden tabs, while the setTimeout-driven procedural runs continue. A live-updating page in a background tab reports thousands of phantom blocks.

**5.28 `characterData` mutations are invisible** (`:785-788`). Frameworks update text nodes in place (React's `commitTextUpdate`), producing no `childList` mutation — so a recycled virtualized row whose label becomes "Promoted" is never re-evaluated. Fix: add `characterData: true`, gated on whether any text-matching rules exist.

**5.29 `:matches-path` verdicts cached across SPA navigations** (`:554-562`) — the per-element result is keyed by `(op, arg)` and the element never becomes dirty on a `pushState`, so `ytd-app #related:matches-path(/watch)` never activates without a hard reload.

**5.30 Element picker offers shadow-DOM candidates it cannot persist** (`element-picker.js:263-286`, `:795-801`). Candidates inside open shadow roots validate, count matches, and preview correctly (all via shadow-piercing helpers), but the saved rule is applied through document-level CSS that cannot enter shadow roots. The user sees success, and the ad returns permanently on reload.

**5.31 Element picker's filter save is an unguarded read-modify-write** (`:765-777`). Two pickers, or a picker plus an options-page edit, silently drop one rule. Fix: an `APPEND_USER_FILTER` message handled atomically SW-side.

**5.32 YouTube player poll gives up permanently** (`youtube-shield.js:68`, `:710-733`). The ~6.15 s bounded chain expires before a background tab constructs its player, and re-arming depends on `yt-navigate` events that focusing a tab doesn't fire. The DOM ad-skipper is then dead for that tab. Fix: re-arm on `visibilitychange`.

### Scriptlets

**5.33 `prevent-xhr`/`m3u-prune` replace `XMLHttpRequest` with a plain function** (`prevent-xhr.js:14, 29-47`), dropping the static constants — so page code testing `xhr.readyState === XMLHttpRequest.DONE` compares against `undefined` and **never runs its completion handler, for every request**. The blocked path fires only `onload`, so `onreadystatechange` listeners hang; `readyState` is defined non-configurable so a reused object throws; and the instance gains own properties native XHR lacks (a one-line detector). Fix: use the `new Proxy(OrigXHR, {construct})` pattern already used correctly in `trusted-replace-fetch-response.js:87`.

**5.34 Detectability cluster.** Literal branding in thrown errors (`abort-on-property-read.js:60`: `` `AdBlock: access to ${prop} denied` ``, plus three more files) makes `try { window._sp_ } catch (e) { /AdBlock/.test(e.message) }` a reliable detector — uBO throws a per-session random token for exactly this reason. `abort-on-stack-trace.js:20` calls `console.log('[Nullify] Silently aborted …')` in a scriptlet whose own message says "silently", leaking the extension's name to any page that has wrapped `console.log`. `bot-stealth.js:41` marks patched functions with an own enumerable property (`Object.keys(getParameter)` → `["__nullifyPatched"]`), and no wrapper anywhere masks `Function.prototype.toString`. The idempotency guard at `abort-on-property-read.js:54` is dead code — it tests `.includes('adblock')` against a getter whose source says `AdBlock`. Fix: one random per-load token for all thrown messages; a module-scope `WeakSet` instead of function properties; one shared `Function.prototype.toString` proxy.

**5.35 `set-cookie-reload` uses one global guard key** (`set-cookie-reload.js:6-7`), checked *before* the cookie is written and not scoped to the cookie name. With two such rules on one origin, rule B's cookie is never set in that tab. The guard also survives legitimate same-origin navigations, permanently disabling the scriptlet there.

**5.36 Leaks.** `no-set-timeout-if.js:7` and `no-set-interval-if.js:7` maintain a `noopTokens` Set that is written to and never read — an ad script polling every 50 ms adds ~20 strings/second forever. `add-class.js:16`, `remove-class.js:17` and `remove-attr.js:21` create MutationObservers that are never stored or disconnected, and `remove-attr` passes `attributes: true` with no `attributeFilter`, so every hover/animation class change in the document schedules a full-document `querySelectorAll`. `remove-cookie.js:15` adds a `beforeunload` listener that is never removed.

**5.37 Assorted uBO semantic gaps.** `set-local-storage-item` has no `$remove$` handling (51 rules write the literal string instead of calling `removeItem`). `prevent-fetch` treats argument 1 as a raw substring, so 49 shipped rules using uBO's `key:value` `propsToMatch` form never match. `trusted-set-constant` sets `configurable: false`, permanently locking the property so any later rule on the same path throws into a swallow. Nothing distinguishes `trusted-*` scriptlets from ordinary ones — they are reachable from any subscribed list *and* from user filters with no trust gate.

**5.38 Scriptlet injection races page scripts** (`service-worker.js:2574-2610`). Up to three sequential `executeScript` round-trips precede injection, all triggered by a message from the content script. Property traps are installed after the page's first inline script has read the flag; `fingerprint-noise` patches `getImageData` after a fingerprinter has cached the pristine reference. Invisible — the scriptlet reports success. Fix: `registerContentScripts({world: 'MAIN', runAt: 'document_start'})`, which also closes §4.24.

### Build, release, CI

**5.39 SRI verification is dead code in every real build** (`build-rules.mjs:138-141`). `rules/filter-list-hashes.json` is gitignored, absent from the repo, and never generated in CI; a missing hash returns `{valid: true}`. Every build — including the tagged release build — fetches 8 lists with zero integrity verification and no warning. Even when present: `!#include` sub-files bypass verification entirely (and uBO lists carry most content in includes), redirects may downgrade to `http://`, and hash-then-refetch is inherently TOCTOU against hourly-updating lists. Fix: commit the lock file, make a missing hash a build failure, hash the fully-expanded text, require `https` on redirects.

**5.40 The release workflow is ungated and supply-chain-soft** **[PARTLY FIXED — gated + version-asserted; SHA pinning and signing still open]** (`.github/workflows/build.yml`). Tag-triggered with `permissions: contents: write`, it runs no lint or tests and has no `needs:` on the test workflow — a tag on a red branch publishes a release. Actions are tag-pinned, not SHA-pinned (`dtolnay/rust-toolchain@stable` is fully mutable; `jetli/wasm-pack-action` pulls `version: 'latest'`), any of which executes third-party code holding a write-scoped token. No checksums or signatures are published. The zip includes `rules/skipped/*.log` build logs, and nothing asserts the tag matches the manifest version — a `v4.2.0` tag will happily ship a 4.1.0 manifest.

**5.41 Dedup key ignores action payload and priority** (`build-rules.mjs:958-967`). `$removeparam=utm_source` and `$removeparam=utm_medium` collide, so only the first parameter is ever stripped; `||y.com^` and `||y.com^$important` collide, discarding the important flag. Fix: include `priority` and `JSON.stringify(rule.action)`.

**5.42 `redirect-rule=` is treated as an unconditional redirect, and redirects lose to blocks** (`:477-482`, `:799-819`). uBO applies `redirect-rule=` only when another filter blocks the resource; here it always redirects. And at equal priority DNR resolves `allow > block > redirect`, so a co-matching EasyList block wins and hard-blocks where uBO would serve a working stub — causing the breakage the redirect exists to prevent. The uBO resource token is captured and discarded; multi-type rules take `resourceTypes[0]`, handing a JS data-URI to image requests.

**5.43 Wildcard `domain=` entries ship as invalid DNR** (`:467-474`) — 148 rules with `initiatorDomains` like `gmx.*` or `southpark.*`, which Chrome rejects at ruleset load with an indexing warning. Silent under-blocking plus load-time warnings in `chrome://extensions`.

**5.44 The RE2 cost estimator over-drops valid patterns** (`:593-601`, `:640`). `.` is costed at 256 and `*`/`+` at ×10, so any pattern containing `.*` blows the 500 budget — but RE2 compiles `.` to one byte-range instruction and never backtracks, which is precisely why Chrome chose it. The skip logs show ~100 regex rules dropped across two lists with claimed costs like 25617, against only 39 kept. The length cap is also still 150, not the 256 prior review 4.4 asked for.

**5.45 Regex filters ending in `$/` are mangled** (`:392-395`) **[verified]**. `/banner[0-9]+\.gif$/` → `urlFilter: "/banner[0-9]+\\.gif"` — the `$` anchor is parsed as an option separator and a regex filter ships as a literal urlFilter containing regex syntax. Fix: when the pattern starts with `/`, treat `$` as a separator only after the closing `/`.

**5.46 Case sensitivity** (`:771-772`). `isUrlFilterCaseSensitive` is never set to false, but DNR defaults to case-sensitive while ABP filters are case-insensitive absent `$match-case`. EasyList's `/adframe.` does not match `.../AdFrame.js`. uBO's converter sets `isUrlFilterCaseSensitive: false` on every rule.

**5.47 Single-part list limits exceed writable capacity** (`:45-56` vs `MAX_PER_FILE`). `annoyances` declares `totalLimit: 30000` with `parts: 1`, but the write loop emits at most 25,000 — up to 5,000 rules vanish with no skip-log record.

**5.48 The build wipes `rules/` before fetching** (`:1679-1680`, `:1785-1787`). One flaky CDN removes the previously-good rulesets and throws before writing new ones, instantly breaking a developer's loaded extension (Chrome silently ignores missing static rulesets — the exact class of bug `verifyManifestRuleResourcePaths` was added for). Fix: stage to a temp dir and swap on success.

**5.49 `system-unbreak.json` blanket `||gstatic.com^` allow at priority 1000** **[verified]** permanently defeats the 8 EasyPrivacy gstatic telemetry blocks (`csi.gstatic.com`, `gen_204`). Fix: scope to `/recaptcha/` and font paths, or to `stylesheet`/`font`/`script` types.

**5.50 `version.mjs` desyncs `package-lock.json`** **[FIXED]** (`version.mjs:36-43`). Lockfile v3 stores the root version twice; only the top-level field is rewritten, so `npm ci` fails on the next CI run. The `npm run version:bump` path is safe because `npm version` rewrites the lock first — the standalone script is the trap.

**5.51 Webpack `splitChunks` covers the content scripts** (`webpack.config.js:60-67`). Today nothing crosses the 20 KB `minSize`, so no shared chunk is emitted — but the first time `src/shared/` does, webpack will emit a common chunk that content scripts cannot load (no chunk-loading runtime), and content filtering dies at page load. Fix: exclude `content` and `youtube-shield` exactly as `service-worker` and `scriptlets-world` already are.

**5.52 Manifest/README drift** **[verified]**. The manifest declares 15 rulesets with 7 enabled, totaling **67,975** enabled static rules — above Chrome's 30,000 guaranteed minimum, so first-run enablement depends on the shared global pool. Two declared rulesets (`easylist_4`, `ubo-filters_2`) ship with 0 rules. The README still describes "6 rulesets" and "~41 (sample), ~150K+ (full)". `docs/REVIEW.md` §11 also lists "Settings import/export ✅", which does not exist at HEAD, and calls the element picker an element zapper.

## 7. Review of Recent Commits

**`18f813a` — "Harden scriptlet boot-key seeding against setter capture".** Right diagnosis, incomplete fix, and the commit message understates the residual. Switching from plain assignment to `Object.defineProperty` genuinely closes the setter-capture leak, and returning `false` so the bundle isn't loaded under an attacker-controlled key is the correct failure posture. But `configurable: true` — chosen so the bundle can `delete` the property — leaves it *replaceable*, not merely readable, and the bundle side (`index.js:178-193`) wasn't updated in this commit: it accepts any non-empty string as the key and swallows a `defineProperty` failure without telling the SW. Together those turn the race from an information leak into a permanent scriptlet kill (§4.24). Deferring the redesign is the right call; the interim state should at least be `configurable: false` plus key-shape validation.

**`8045c14` — "Fix WASM panics on corrupt input and unreachable generic scriptlets".** Solid work at the right layer: validating `size`/`hashes`/`data.len()` before first use rather than defensively inside `has()`; replacing `line.len()-1` with `rfind(')')` plus a `close < open` guard, which fixes both the `start > end` panic and the non-char-boundary panic in one change; and normalizing `domains: []` → `['']` at the `putBulkScriptletRules` chokepoint rather than at each query site. Rust regression tests were included for both panic paths. Two follow-ups: (a) the validation arithmetic itself overflows on wasm32 and re-opens the OOB panic (§4.2); (b) `DB_VERSION` is still 4 and `ensureRuleDataReady` rebuilds only when the bundled rule-data hash changes, so existing installs keep their pre-fix rows with `domains: []` and generic `##+js(...)` rules stay unreachable there. If the fix was meant to reach existing users on update, bump `DB_VERSION` or force a recompile on `details.reason === 'update'`.

## 8. Test Gaps

The four highest-value additions, ordered by defects-caught-per-line:

1. **A serializing message-bus fixture.** Every SW↔content message in tests should pass through `JSON.parse(JSON.stringify(...))`. This alone catches §3.1, the single worst defect in the codebase, and prevents the whole class.
2. **A scriptlet-corpus conformance test.** Load `rules/scriptlet-rules.json`, resolve every rule against the registry, and assert the unknown-name rate stays below a threshold. Catches §3.6 and, with per-scriptlet argument fixtures, §3.8, §4.23 and §4.34.
3. **A DNR conversion golden-file suite.** `parseLine` and `networkFilterToDNR` are already exported; a table of filter-line → expected-rule pairs covering the modifier dispatch, priority scheme, pattern conversion and regex pipeline would have caught §3.3, §3.4, §4.10, §4.21 and §5.45 outright. The current `build-rules.test.mjs` covers 5 cases, none in these areas.
4. **Cross-engine golden vectors for the parsers.** One fixture list run through `wasm-core`, `filter-parser.js` and `build-rules.mjs`, asserting identical output. This is the structural fix for the parser-drift class (§4.3, §4.4, §4.10) — it turns a whole category of silent divergence into a failing test.

Also worth adding: a build-time assertion that no `urlFilter` contains `##` (§4.20), and that `malware.json` contains at least one `main_frame` rule (§3.5).
