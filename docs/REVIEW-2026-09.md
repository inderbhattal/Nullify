## 1. Executive Summary

The 2026-08 remediation is real and mostly holds (§2). The three P0s of that cycle are fixed as prescribed and each has a harness test that fails on the prior code. The debt did what it did last time: it moved into the seams — this time into three specific shapes, each of which produced a P0.

1. **A single failed `chrome.storage.local.get` wipes the allowlist or the user's filters, with a success response** (§3.1). `getStorageBulk` was changed in the 2026-07 cycle (§5.11) to resolve `{}` when `chrome.runtime.lastError` is set. Every allowlist and user-filter read-modify-write now reads through it, so a transient read fault reads as "empty" and is committed: `ALLOW_SITE` leaves one entry (the shape 2026-08 §3.1 fixed, reopened through a different door), the startup reconcile deletes every stored entry **and every DNR allow rule with no user action and no error reported**, and the element picker's `APPEND_USER_FILTER` replaces the whole My Filters text with the one picked line. All three reproduced in the harness.
2. **191 uBO cosmetic rules on 289 domains silently kill every domain-specific CSS hide on those sites** (§3.2). Five uBO operators Nullify never learned — `:remove-attr()`, `:others()`, `:remove-class()`, `:shadow()`, `:matches-media()` — pass the CSS-safety gate as if they were CSS and are comma-joined into the site's one declaration. A browser discards a declaration with any invalid selector. This is exactly the failure 2026-08 §5.13 described and half-closed: pseudo-elements and leading combinators were gated, unknown pseudo-classes were not.
3. **The primary user-filter compiler still strips modifiers it does not understand and ships the broadened rule** (§3.3). `compile_user_filters` in wasm-core turns `||facebook.com^$removeparam=fbclid` into a hard block of `facebook.com`, `$csp=` into a block, `$to=`/`$from=`/`$method=`/`$header=` into unscoped blocks, and `@@…$genericblock` into a blanket allow. That is 2026-07 §3.4 — a P0 then — fixed in the build parser, fixed again in the JS fallback (2026-08 §5.6), and never in the Rust engine that actually runs whenever WASM is healthy. Pasting a `$removeparam` list into My Filters is the most ordinary thing a uBO refugee does.

Beneath those, the P1s cluster around two patterns the previous review also named:

- **Fixes that stopped at a file boundary.** `$all` got `main_frame` coverage for `malware.json` only; 1,379 badware.txt host blocks still cannot stop a navigation (§4.1). The `!#include` fail-closed fix reached the build and not the runtime refresh, which now stores a truncated list over a good one and reports success (§4.3). The scriptlets got `maskNative`/`proxyApply`; the YouTube shield — the file carrying the headline feature — still wraps `JSON.parse`, `fetch` and `XMLHttpRequest` in the exact detectable shapes §4.22/§5.21 removed elsewhere (§4.4).
- **A freshness model that is documented but not implemented.** The README's argument for vendoring `quick-fixes.txt` rests on the 24-hour runtime refresh. Measured: a fresh install does not refresh for 24 hours, an extension update rolls every runtime-refreshed list back to the release snapshot and leaves the alarm at 24 hours, and the interval is 24 hours against a list that declares `Expires: 8 hours` (§4.5).

Two systemic observations for the maintainers. First, **coverage is now measurable and the numbers are good**: scriptlet resolution is 95.8% corpus-wide, and 734 dropped network rules (`$to=`, `$denyallow=`, `$from=`, `$method=`, `$header=`, and scoped `*` patterns) map one-to-one onto DNR fields the build simply never learned (§4.2). Second, the two engines that share a job keep disagreeing in the *safe-looking* direction: the JS fallback CSS builder emits one rule per selector and would have survived §3.2; the JS fallback user-filter parser fails closed and would have survived §3.3. The primary path is the less careful one in both cases, which is the wrong way round.

**Recommended gate before any further feature work:** §3 in full. §3.1 is a one-function change with a harness test; §3.2 is a two-line gate in two engines plus three cheap operators; §3.3 is a `return None` in three match arms.

## 3. P0 — Ship Blockers

### 3.1 A swallowed `lastError` on a storage read turns every allowlist / user-filter read-modify-write into a wipe **[verified]**

**Where:** `src/shared/storage.js:66-79` (`getStorageBulk`, resolves `{}` at `:72-75`); consumers `src/background/service-worker.js:2915-2917` (`readStoredAllowlist`), `:2930-2938` (`allowSite`), `:2971-2979` (`disallowSite`), `:2951-2961` (`addAllowlistDomains`), `:1418-1461` (`refreshMemoryCache`, reconcile at `:1445-1456`), `:2785-2798` (`appendUserFilterLine`, read at `:2787`).

**Issue.** 2026-07 §5.11 made `getStorageBulk` "honour `chrome.runtime.lastError` and keep the returns-null contract instead of throwing". It now resolves `{}` whenever the callback fires with `lastError` set or an `undefined` result. That converted a *loud* failure (a `TypeError` that rejected the whole chain and wrote nothing) into a *quiet* one that every downstream writer treats as authoritative "empty":

- `readStoredAllowlist()` → `[]` → `allowSite` composes `[newDomain]` → `_rebuildAllowlistStateNow` commits it to storage and DNR. This is 2026-08 §3.1's exact outcome — the fix moved the base list from the memory cache to storage, and storage can now lie.
- `refreshMemoryCache()` on **every service-worker start** reads `ALLOWLIST` in a bulk get; a failed read yields `rawAllowlist = []`, `needsNormalization` is false (0 vs 0), and the §4.7 reconcile sees `dnrAllowRuleCount (N) !== 0` → `rebuildAllowlistState([])` → storage set to `[]` and every `allowAllRequests` rule deleted. No user action, and nothing reaches `reportError`.
- `appendUserFilterLine()` reads `USER_FILTERS`; a failed read yields `''`; the picked line becomes the *entire* filter text and is applied.

**Evidence.** Harness, fresh worker per scenario, one `storage.local.get` made to report `lastError` once (`exp10-sw.mjs` 10d, `exp10b-sw.mjs` 10d2/10d3):

```
10d  stored before:  ["bank.example","mail.example","work.example"]
     ALLOW_SITE →    {"ok":true,"allowlist":["news.example"]}
     stored after:   ["news.example"]      dynamic allow rules: ["||news.example^"]

10d2 (startup, no user action)
     stored allowlist after boot: []       dynamic allow rules after boot: []
     errorReport: 1 critical (the harness's own WASM failure), 0 warnings — nothing about this

10d3 userFilters before: "||ads.example^\nexample.com##.ad\n"
     APPEND_USER_FILTER → {"ok":true,"counts":{"network":0,"cosmetic":1,…}}
     userFilters after:  "site.example##.picked"
```

`src/shared/storage.test.mjs` pins the `{}`-on-`lastError` behaviour, which is why no existing test catches this.

**Impact.** Data loss with a success response, on the two pieces of state the user authored by hand, triggered by an I/O fault the extension did not cause. The frequency of `storage.local.get` failing is low (profile-level I/O errors, storage unavailable during startup/shutdown); the previous cycle's §3.1 also needed an unusual trigger and was rightly a P0, because the failure direction is irreversible and invisible.

**Remediation.** Reads that feed a write must not degrade to "empty". Concretely: (1) `getStorageBulk` rejects (or returns a distinguishable sentinel) on `lastError`; keep a separate `getStorageOrDefault` for read-only consumers that want the old contract. (2) `readStoredAllowlist`, `appendUserFilterLine` and `addAllowlistDomains` propagate the rejection, so the handler answers `{error}` and nothing is written. (3) `refreshMemoryCache` must not reconcile when the read failed — skip the DNR compare and `reportError` instead. (4) `restorePersistedStats` should treat a failed read as "unknown", not "zero", or the stats zeroing §4.14 fixed returns through this door.
**Regression tests (fail today):** the three scenarios above as `tests/sw-harness/sw-storage-faults.test.mjs`; plus an update to `storage.test.mjs` asserting a failed read rejects.

### 3.2 Unknown uBO cosmetic operators pass the CSS gate and invalidate every domain-specific hide on 289 sites **[verified]**

**Where:** `wasm-core/src/lib.rs:2039-2046` (`is_css_safe_selector`), `:1913-2037` (`has_invalid_universal_usage` — only `::` pseudo-elements are checked), `:1530-1553` (`proc_op_ac`, the operator set), `:2048-2071` and `:2302-2328` (the two comma-joining CSS builders); JS mirror `src/background/service-worker.js:707-806`; content side `src/content/cosmetic-engine.js:403-414` (`hasCustomOp` list).

**Issue.** uBO's procedural dialect includes action operators Nullify does not implement: `:remove-attr()`, `:remove-class()`, `:others()`, and the predicates `:matches-media()`, `:shadow()` (also `:matches-prop()`, zero in this corpus). None is in `PROC_OPS`/`proc_op_ac`, so `contains_proc_op` is false; the safety gate rejects unknown *pseudo-elements* (`::before2`) but not unknown *pseudo-classes*, so `div:others()` is "CSS-safe" and is joined with up to 149 other selectors into one declaration. Per CSS Selectors 4, a selector list containing an invalid selector invalidates the whole rule (only `:is()`/`:where()` are forgiving). A site's domain-specific selectors almost always fit one chunk, so one such rule takes every hide rule on that site with it.

**Evidence.** Corpus scan of every non-exception `##`/`#?#` rule for functional pseudo-classes that are neither native CSS nor Nullify operators (`exp1-corpus.mjs` EXP 1):

| operator | rules | generic | lists |
|---|---|---|---|
| `:remove-attr(` | 81 | 0 | annoyances, cookie-annoyances, ubo-filters, unbreak |
| `:others(` | 68 | 0 | ubo-filters |
| `:remove-class(` | 32 | 0 | annoyances, ubo-filters, unbreak |
| `:shadow(` | 5 | 0 | ubo-filters |
| `:matches-media(` | 5 | 0 | ubo-filters |

289 distinct domains carry at least one. Driving the shipped artifact:

```
build_css_from_selectors('.good-one\ndiv:others(.x)\n.good-two\n.a >>> .b\n.good-three', '', 100)
→ ".good-one,div:others(.x),.good-two,.a >>> .b,.good-three { display: none !important; … }"

build_page_bundle(['.good-one','div:others(.x)','.good-two','.a >>> .b'], [], [], 100).cssText
→ ".good-one,div:others(.x),.good-two,.a >>> .b { display: none !important; … }"
```

(`>>>` is included because the gate accepts it too; it does not occur in hide rules in this corpus, only in scriptlet arguments.) The JS fallback builder (`buildCssFromSelectorList`, one rule per selector) would have confined the damage to the single bad rule — the primary path is the fragile one.

**Impact.** On each of the 289 sites every domain-specific CSS hide is dead, silently: the browser drops the declaration without any signal the extension can observe, the popup shows the site as protected, and the skip logs record nothing because the build classified the line as a valid cosmetic rule. Real examples include `padlet.com`, `substack.com` (`html.show-intro-popup:remove-class(show-intro-popup)`), `surreyhillsgrocer.sg`, `glosbe.com`, and 68 `:others()` sites in `ubo-filters`. Generic rules are unaffected (0 generic).

**Remediation.** Two independent changes, both cheap: (1) **Gate**: in `has_invalid_universal_usage` (and its JS mirror), treat a single-colon functional pseudo-class as invalid unless its name is in an allowlist of native functional pseudo-classes (`not is where has nth-child nth-last-child nth-of-type nth-last-of-type lang dir host host-context state`) or in the procedural operator set; a rejected selector is dropped alone, never joined. (2) **Operators**: add `remove-attr`, `remove-class` and `others` to `PROC_OPS` in all three places and implement them in `_applyOp` (`:others()` hides every element not on the matched set's ancestor/descendant path — uBO's semantics — and `:remove-attr`/`:remove-class` are two-liners); classify `:matches-media()`/`:shadow()`/`:matches-prop()` as procedural and fail them closed until implemented. Unify `PROC_OPS` into `src/shared/` while there — the 2026-08 §0 already asked for it, and this finding is what three hand-kept copies cost.
**Regression tests (fail today):** `wasm-parity.test.mjs` — `build_css_from_selectors` output must not contain `:others(`/`:remove-attr(`; `cosmetic-engine.test.mjs` — the three new operators; a corpus test asserting that no selector reaching either CSS joiner contains a functional pseudo-class outside the known sets.

### 3.3 `compile_user_filters` strips unsupported modifiers and ships the broadened rule — 2026-07 §3.4 alive in the primary engine **[verified]**

**Where:** `wasm-core/src/lib.rs:1160-1368` (`parse_network_rule_to_dnr`): first-`$` split at `:1164-1167`; `"csp" | "rewrite" | "removeparam" | "redirect" | "redirect-rule"` counted then *ignored* at `:1261-1263`; unknown `key=value` ignored at `:1264`; unknown flags ignored at `:1322`; the elemhide-family refusal at `:1277-1280` omits `genericblock`. Called from `compileUserFiltersViaWasm` (`service-worker.js:2498-2507`), which is the path taken whenever WASM initialised — the JS fallback that was made fail-closed in 2026-08 §5.6 only runs when it did not.

**Issue.** The 2026-07 review made "unknown modifiers are stripped and the broadened rule ships" a P0 (§3.4) and it was fixed in `scripts/build-rules.mjs` (`IGNORABLE_OPTIONS` + drop-otherwise) and later in `parseSimpleNetworkRule`. The Rust user-filter compiler kept the pre-fix behaviour: it recognises a handful of options, counts a few as "unsupported" for a diagnostic nobody reads, and emits the rule regardless.

**Evidence.** Shipped artifact, `compile_user_filters(line, 900000)` (`exp1-corpus.mjs` EXP 2, `exp7-misc.mjs` EXP 20):

```
||facebook.com^$removeparam=fbclid     → block  ||facebook.com^
||example.com^$csp=script-src 'self'   → block  ||example.com^
||example.com^$to=cdn.example          → block  ||example.com^   (scope lost)
||example.com^$from=site.example       → block  ||example.com^   (scope lost)
||example.com^$method=post             → block  ||example.com^
||example.com^$header=content-type:image → block ||example.com^
||example.com^$popunder / $strict3p    → block  ||example.com^
@@||example.com^$genericblock          → allow  ||example.com^   (blanket)
/ads\.js$/$script                      → urlFilter "/ads\.js"    ($ anchor split as options; type lost)
```

**Impact.** The most common thing a user pastes into My Filters is a list snippet, and the most common list snippet in 2026 is URL-tracking hygiene (`$removeparam=utm_*`, `fbclid`, `gclid`): every such line becomes a hard block of the named domain. `$csp` lines from uBO's anti-adblock sections become blocks. `$to=`/`$from=`-scoped rules become unscoped. A `@@…$genericblock` becomes "disable all blocking here". The UI reports "Applied N network rules" for all of it. Which of two behaviours a user gets depends on whether WASM initialised — the divergence the parity suite exists to catch, in the one function it does not cover (`wasm-parity.test.mjs` asserts user-filter *priorities*, never option handling).

**Remediation.** Mirror the build parser's contract in `parse_network_rule_to_dnr`: an explicit ignorable set, `return None` for every option not mapped (both the `key=value` and the flag arms), `genericblock` added to the refusal list, and the option split done with the build's `splitPatternAndOptions` rule (scan `$` right-to-left for a tail that parses as an option list) so regex anchors survive. Map what DNR expresses directly while there: `$to=`→`requestDomains`, `$from=`→`initiatorDomains`, `$method=`→`requestMethods`. Surface the drop count that already exists (`unsupported_opt_drop_count`) through the `skippedRules` channel the UI now renders.
**Regression tests (fail today):** Rust unit tests for each line above asserting no rule (or the correctly scoped rule) is emitted; a `wasm-parity.test.mjs` case that feeds the same lines through `parseSimpleNetworkRule` and the build parser and asserts all three engines agree on drop-vs-emit.

## 4. P1 — Correctness

### 4.1 `$all` loses `main_frame` outside the malware list — 1,379 badware.txt host blocks cannot stop a navigation **[verified]**

**Where:** `scripts/build-rules.mjs:405-416` (`IGNORABLE_OPTIONS` includes `'all'`, with the comment "Ignoring it yields all types except main_frame, which is narrower"), `:1092` (`SECURITY_LIST_IDS = new Set(['malware'])`), `:1275-1281` (`coverDocuments` pins the full set only for that list).

**Issue.** uBO's `$all` means every resource type *including the document*; the whole reason badware.txt writes `||host^$all` is to block the page itself. The 2026-07 §3.5 fix pinned `main_frame` for `malware.json` and left `$all` as an ignorable option everywhere else, so on the `anti-adblock` ruleset (badware.txt, enabled by default) the option is discarded and the rule matches every type except the navigation.

**Evidence.** `parseLine('||bad.example^$all')` → `resourceTypes: []`; `networkFilterToDNR` → `{urlFilter: "||bad.example^", isUrlFilterCaseSensitive: false}` with no `resourceTypes`. Corpus: `anti-adblock.txt` has 1,388 `$all` lines, 1,379 of them `||host^$all`; `ubo-filters.txt` 94 (88 host-anchored). `malware.txt`'s 7,748 are covered by the list-level pin.

**Impact.** A user who clicks through to a listed scam/malware host loads the page; only its subresources are blocked — the outcome §3.5 was written to prevent, on the list uBO maintains specifically for badware.

**Remediation.** Map `$all` to `SECURITY_LIST_RESOURCE_TYPES` (main_frame included) in `parseOptions`, for every list; keep the malware-list pin as the fallback for type-less rules. **Test (fails today):** `||bad.example^$all` → `condition.resourceTypes` includes `main_frame`; `dnr-conversion.test.mjs` "ordinary lists are unaffected — no implicit main_frame" stays green because it covers the type-less case, not `$all`.

### 4.2 734 network rules are dropped whose shape DNR expresses one-to-one **[verified]**

**Where:** `scripts/build-rules.mjs:760-846` (`parseOptions`: no arm for `to=`, `from=`, `denyallow=`, `method=`, `header=`; the fail-closed default at `:837-842` drops them); `options.requestDomains` is declared at `:766` and never populated; `:1384` (`convertPatternToUrlFilter` rejects `*`/empty patterns before the options are considered).

**Issue.** The fail-closed default is correct policy; the mapping table behind it predates uBO's move to `$from=`/`$to=` (the modern spellings of `$domain=` and request-domain scoping) and never covered `$denyallow=`. All five are direct DNR fields: `$to=` → `requestDomains`, `$from=` → `initiatorDomains`, `$denyallow=` → `excludedRequestDomains`, `$method=` → `requestMethods`, `$header=` → `responseHeaders` (Chrome ≥ 128; this one needs a `minimum_chrome_version` decision). A sixth class is a pattern problem, not a modifier: uBO's `*$script,3p,domain=x` ("block all third-party scripts on x") has no URL component, and the converter rejects it as matching everything without noticing the scope.

**Evidence.** Corpus-wide skip records from `parseFilterList` over the vendored lists (`exp1-corpus.mjs` EXP 3c):

| dropped modifier | rules | where |
|---|---|---|
| `$to=` | 304 | anti-adblock 233, ubo-filters 69, unbreak 2 |
| `$denyallow=` | 237 | ubo-filters 235, quick-fixes 2 |
| `$from=` | 35 | ubo-filters 23, unbreak 8, … |
| `$method=` | 29 | ubo-filters 18, anti-adblock 7, … |
| `$header=` | 14 | ubo-filters 10, quick-fixes 3, … |
| `*`/empty pattern with `$domain=`/type/party scoping (`convertPatternToUrlFilter` rejects the pattern as "matches everything" before looking at the options; `build-rules.mjs:1384`) | 115 | ubo-filters (e.g. `*$script,3p,domain=x` ×22, `*$media,domain=x,redirect=` ×11), easylist (`$websocket,domain=pornhub.com|…`), easyprivacy (`$ping,third-party`) |

All 115 `*`-pattern rules are scoped (none is a bare match-everything); DNR expresses them as a condition with `resourceTypes`/`initiatorDomains`/`domainType` and no `urlFilter`. Samples of the modifier drops: `*$script,3p,denyallow=googleapis.com,domain=skidrowcodexgames.com` (the CDN-preserving pattern §3.4 of 2026-07 called out), `.com/c/*?s1=$doc,to=com` (badware redirect chains). For reference the other large drop classes are genuinely inexpressible: `redirect-rule=` 448+38, `$popup` broad 223, `$csp` 78+5 (see §7).

**Impact.** Coverage loss on exactly the lists that carry uBO's anti-circumvention and badware work; the `$denyallow` rules in particular are the "block third-party scripts except these CDNs" shape that unbreaks sites.

**Remediation.** Add the five arms to `parseOptions`; emit `requestDomains`/`excludedRequestDomains`/`requestMethods` in `networkFilterToDNR`; normalise the domain lists through `normalizeDomainList` (the §5.29 work) and drop on unencodable exclusions the same way `$domain=` does. `$header=` behind a build flag until the Chrome floor is raised. For `*`/empty patterns, emit a condition without `urlFilter` when at least one of `resourceTypes`/`initiatorDomains`/`domainType` scopes it, and keep dropping the genuinely unscoped form. **Tests (fail today):** one `dnr-conversion.test.mjs` vector per modifier asserting the emitted condition field, one for `*$script,3p,domain=x.com` asserting a urlFilter-less scoped condition; extend `chrome-stub.validateDnrRuleSchema` to `requestMethods`.

### 4.3 The runtime `!#include` path fails open and stores a truncated list over a good one, reporting success **[verified]**

**Where:** `src/shared/filter-parser.js:468-485` (`fetchAndExpand`: include failure → `console.warn` + `''`), consumed by `src/background/service-worker.js:916-948` (`fetchAndStoreRemoteFilterSources` stores whatever came back and lists the id in `updatedLists`).

**Issue.** 2026-08 §5.10 made the *build* refuse a list whose sub-file failed. The runtime copy of the same function kept the fail-open branch, and the runtime is now the *only* channel by which `quick-fixes.txt` and the uAssets lists (all of which carry their content in `!#include`d sub-files upstream) reach installed users between releases. ### 4.4 The YouTube shield is trivially fingerprintable and carries the own-property / `toString` leaks §4.22 and §5.21 removed from the scriptlets **[verified]**

### 4.5 The quick-fixes freshness model the README relies on does not hold **[verified]**

**Where:** `src/background/service-worker.js:1993-2020` (`scheduleFilterUpdateAlarm`: first delay = full interval when `LAST_UPDATE_CHECK` is absent), `:1176-1182` (`ensureRuleDataReady` on a version change: `putBulkFilterSources(packaged)` overwrites every stored list), `:59` (`FILTER_UPDATE_INTERVAL_MINUTES: 1440`); README "ubo-quick-fixes is the volatile one" section.

**Issue.** The README argues that vendoring an `Expires: 8 hours` list is acceptable because "those are re-fetched by the service worker on its own 24 h alarm". Three things defeat that in practice: a fresh install never writes `LAST_UPDATE_CHECK`, so the first refresh is 24 hours after install; an extension update (the only way static rules change) rolls every runtime-refreshed list back to the release snapshot and leaves the alarm where it was; and 24 hours is three times the list's declared expiry.

**Evidence.** Harness (`exp10-sw.mjs` 10a/10b):

```
10a fresh install:  filter-list-update alarm {delayInMinutes: 1440, periodInMinutes: 1440}; lastUpdateCheck undefined
10b after a runtime refresh stored ".fresh-from-runtime-refresh" for ubo-quick-fixes, a boot with a
    changed bundled version stored: ["ubo-quick-fixes:.packaged-snapshot"]; alarm still 1440 min out
```

**Impact.** The YouTube counter-moves the product was reworked around in PR #11 reach a new install a day late, and every release *un-refreshes* them. This is a product-level contradiction between the documented mitigation and the code rather than a bug in either alone.

**Remediation.** On `onInstalled` (`install` and `update`) schedule an immediate refresh (a one-shot alarm at +1 min, so it survives the install-time SW churn); on a version change merge packaged sources with `fetchedAt` stamps and keep whichever is newer per list; honour `! Expires:` per list (parse the header, floor at 2 h, cap at 24 h) so quick-fixes refreshes on its own cadence. **Tests (fail today):** 10a asserts a sub-hour first delay; 10b asserts the fresher source survives the update boot.

### 4.6 Re-prioritization: document_start scriptlet injection (2026-07 §5.38, open by decision) **[by inspection, partly measured]**

**Where:** `src/background/service-worker.js:3496-3655` (`injectScriptlets` → `ensureScriptletRegistry`: up to four `executeScript` round trips, then a fifth to run specs), reached only after the content script's `GET_INIT_DATA` message (`content-main.js:76`); the shield, by contrast, is registered at `document_start` in MAIN world by `youtube-shield-sync.js:50-61`.

**Why re-raise it.** The prior reviews deferred moving scriptlets to `registerContentScripts({world: 'MAIN', runAt: 'document_start'})` as a design decision. PR #11 changed the product's dependence on the current path: it ingested `quick-fixes.txt` for rules that must hook `fetch`, `XMLHttpRequest`, `JSON.parse` and `ytInitialPlayerResponse` before page code captures them (`trusted-replace-fetch-response`, `json-prune-fetch-response`, `trusted-rpnt`, …), and the remediation spent a track making 13.9k scriptlet rules argument-correct. All of them are still injected late: message to the SW, cold-start gate, cosmetic lookup, then 2–5 MAIN-world IPCs (the harness records two `executeScript` calls *before* the `GET_INIT_DATA` response is even sent — `exp10-sw.mjs` 10h). Inline `<script>` in the document head runs before any of that. `abort-on-property-read`, `abort-current-inline-script` and `set-constant` — the bulk of the corpus — are precisely the rules whose value is decided by that race. The seed→load boot-key mitigations (§4.24 of 2026-07, three layers) exist only because of this architecture.

**Recommendation.** Treat this as the top parity feature (§7.1) rather than an open decision: one registered MAIN-world bundle with per-site specs delivered by the SW through `chrome.storage.session` or by regenerating the registered script on rule change, matching uBO Lite. It also retires `SCRIPTLET_REGISTRY_KEY`, `seedBootKey` and `verifyScriptletRegistry` wholesale.

## 5. P2 — Hardening

### Service worker

**5.1 The sequential ruleset fallback disables every ruleset first, on every SW start while the batch failure persists** [verified] (`service-worker.js:3177-3214`, `:3252-3274`). When the batch `updateEnabledRulesets` fails — the rule-limit case happens whenever another DNR extension consumes the shared static pool — the fallback starts with `disableRulesetIds: [all]` and re-enables one at a time. Harness sequence: `disable=[system-unbreak,easylist,easylist_2,easyprivacy,ubo-quick-fixes]` then five single enables. `applyRulesets` runs in `ensureBackgroundSetup` on *every* worker start, so the window of zero network blocking recurs every wake for as long as the pool stays short. Fix: compute the delta against `getEnabledRulesets()` and only disable what must go; never disable `system-unbreak`/`ubo-unbreak` in the reset.

**5.2 The privacy DNR rules and the allowlist reconcile are rewritten on every cold start** [verified] — six `updateDynamicRules` calls per start (`exp10-sw.mjs` 10i), plus a `getDynamicRules`. Dynamic rules persist; `applyPrivacySettings` (`:1737-1787`) should compare before writing. Related: a fresh install runs the full active-index rebuild **twice** (`onInstalled` and module-load `startInitialization` both call `ensureRuleDataReady`; two `ruleIndexState=building` writes observed, 10e).

**5.3 `IS_SITE_ALLOWED` and `GET_TAB_STATS` are `SENDER_ANY` with only extension-page callers** [verified] (`:3746-3747`; callers `popup.js:96,137,198` only). A content script on `evil.example` asking `IS_SITE_ALLOWED {domain: 'bank.example'}` receives `{allowed: true}` — an allowlist-membership oracle over any hostname. Move both to `SENDER_EXTENSION_PAGE`; the §5.4 tab-id guard in `GET_TAB_STATS` becomes moot.

**5.4 `CHECK_SEMANTIC_AD` accepts unbounded text from any renderer** [verified] (`:4092-4096`; `lib.rs:4040-4051` has no `check_input_size`). 64 MB of `x` → 684 ms in WASM and a permanent linear-memory growth; the engine itself never sends more than 400 chars (`cosmetic-engine.js:956`). Cap at 1 KB server-side and in Rust.

**5.5 Navigation handlers re-seed the memory cache unconditionally** [by inspection] (`:4426`, `:4468`). §5.4 of 2026-08 gated `setCachedDomainRules` inside `getCosmeticBundleForPage` on the rebuild generation; both navigation callers then call it again ungated on the returned bundle. The practical window (a lookup computed against half-cleared stores that resolves after the rebuild's own `domainRulesCache.clear()`) is small; the fix is to delete the two calls and let the gated setter own the cache.

**5.6 `@@…$document` compiles to `allow` on `main_frame` only** [verified] (`build-rules.mjs:1273-1274`, `:1302-1303`; 13 rules, e.g. `@@||ad.admitad.com/g/*&ulp=http$doc`). uBO's `$document` exception disables *all* filtering for the page; DNR's equivalent is `allowAllRequests` on `main_frame`/`sub_frame`. Same family, smaller: `$elemhide` (3) and `$specifichide` (1) collapse into the generic-hide exclusion set (`filter-parser.js:302-307`, `build-rules.mjs:1535-1538`), so `$elemhide` still applies domain-specific cosmetics and `$shide` does nothing.

**5.7 Exception CSS is a cascade override, not a set subtraction** [verified mechanism] (`lib.rs:2079-2092`, `service-worker.js:861-863`, appended after the hide sheet by `content-main.js:96`). `build_page_bundle([], ['.ad','.foo.promo'], ['.foo'])` emits `.ad,.foo.promo {display:none!important}` and `.foo {display:revert!important}`; an element matching both stays visible, whereas uBO's `#@#.foo` only removes the `.foo` rule. A syntactic scan found no same-domain hide/exception prefix pair in the corpus, so this is latent — but it is also unnecessary: exact-match subtraction already happens (`suppression_set`), and the revert sheet can be dropped for selectors that were subtracted.

**5.8 `getPageBundle` is a `readwrite` transaction on every page load** [by inspection] (`db.js:359-382`, LRU stamp rewrite). It contends with the rebuild's write locks and turns a cache hit into a disk write; stamp in memory and flush on prune instead.

**5.9 The stealth personas are frozen at Chrome 122** [by inspection] (`service-worker.js:1878-1894`, `persona-spoof.js`, `bot-stealth.js`). In September 2026 a UA/`sec-ch-ua` claiming Chrome 122 is a beacon, not camouflage, and some sites gate on major version. Derive the major from `navigator.userAgentData` at runtime or refresh on release.

### Content scripts

**5.10 Page-visible fixed markers** [by inspection]. Every element the procedural engine hides is stamped `__adblock_hidden__="1"` (`cosmetic-engine.js:28`, `:1252`), and the injected sheets carry fixed ids `__nullify_frame_css__` / `__nullify_exception_css__` (`content-main.js:18-19`). `document.querySelector('[__adblock_hidden__]')` is a one-line blocker detector, and the `<style>` copy is page-removable (the `insertCSS` copy from `performEarlyInjection` is not, so removal only matters when that path failed). Track hidden elements in the existing `WeakSet` and drop the attribute; randomise or drop the style ids.

**5.11 The same CSS is injected twice per frame** [by inspection]: `performEarlyInjection` (`insertCSS`, user origin) and the content script's `<style>` (author origin) both carry `cssText`, into every frame including third-party ad frames about to be blocked. Keep `insertCSS` as primary and inject the `<style>` only when the SW reports it could not.

### Rust core / shared

**5.12 The curated PSL admits eleven common second-level suffixes as allowlist entries** [verified] (`psl.js:18-54`, `hostname.js:74-84`): `co.th co.id com.my com.ph com.vn com.pk com.ng com.sa co.ke com.pe com.co` (and platform suffixes `blogspot.com`, `wordpress.com`) all pass `isValidAllowlistDomain`, so an import line or typo yields `||co.th^` + `allowAllRequests`. Generate `psl.js`/`psl_generated.rs` from the real PSL (ICANN section, ~9k entries, ~60 KB gzipped) rather than curating.

**5.13 Dead code shipped in the tree: `src/shared/jsonpath.js` (1,298 lines) has no importer** [verified: `grep` finds only its own test]. It was built as the foundation for `json-edit`/`trusted-json-edit-*` (61 corpus rules, 13 of them YouTube quick-fixes) and never wired. Either wire it (§7.4) or move it out of `src/`.

### Build, CI, release, docs

**5.14 `build:rules` output depends on whether a WASM artifact happens to be present** [by inspection] (`build-rules.mjs:2553-2571`, `:2649-2656`): with the artifact, `filter-sources.json` comes from `parse_filter_source`; without it, from the JS fallback, with a warning. Two developers can commit-and-ship different bundles from the same snapshots. Fail the non-sample build when the Rust parser is unavailable (CI always builds it first).

**5.15 CI clippy runs without `-D warnings`** [verified: `.github/workflows/test.yml:91`]. The docs claim "clippy -D warnings clean"; it is (verified today), but CI would not notice if it stopped being.

**5.16 `check-test-prereqs` checks existence, not freshness** [by inspection] (`scripts/check-test-prereqs.mjs:14-29`). A stale `src/shared/wasm/` artifact — the state this session started in — passes the check and produces failures that look like product bugs (8 in this case, per the session notes). Compare the artifact's mtime (or a recorded source hash) against `wasm-core/src/*.rs` and `Cargo.lock`, and say "stale" rather than "missing". Related test gap: the suite passes with `rules/*.json` and `dist/` absent (verified after they disappeared mid-session, §9), i.e. **no test opens a compiled ruleset**; a single test that loads each `rules/*.json` referenced by the manifest and validates schema/IDs/regex counts would catch a broken build before Chrome silently drops the ruleset.

**5.17 Registry coverage and docs drift** [verified numbers]. 592 of 13,934 corpus scriptlet rules (4.2%) resolve to nothing; the top gaps are cheap: `noeval-if` 152, `nowebrtc` 59, `trusted-suppress-native-method` 24, `nobab` 21, `popads-dummy` 19, `xml-prune` 19, `nofab` 18, `set-attr` 7+8. `quick-fixes.txt` resolves 100 of 161 (13 of its 32 YouTube rules are unresolved — `trusted-replace-outbound-text` 4, `trusted-json-edit-xhr-request` 4, `trusted-prevent-dom-bypass` 3). Popup and options both hand-maintain the list-name tables (`popup.js:11-21`, `options.js:18-28`) that PR #11 already forgot once.

## 7. Recommended Features

Ranked by user value against effort; each with the MV3 mechanism, its limits, and where it lands. "Impossible" is stated where MV3 genuinely forbids it.

1. **Document_start scriptlets via `chrome.scripting.registerContentScripts({world:'MAIN', runAt:'document_start'})`** — parity; the single largest correctness lever left (§4.6). Design: one registered MAIN bundle for `<all_urls>`; per-site specs published by the SW into `chrome.storage.session` keyed by hostname (readable from an ISOLATED helper that posts them into MAIN via a `CustomEvent` before `document_start` scripts of the page run — uBO Lite's approach), or regenerate a per-host registered script on rule change. Limits: registered scripts persist across sessions (good); MAIN-world scripts cannot call `chrome.*`, hence the ISOLATED relay. Touches: `service-worker.js` (delete the boot-key machinery), `scriptlets/index.js`, `youtube-shield-sync.js` (share the registration code), manifest. Effort L.
2. **Runtime-compiled dynamic rules for the volatile list + `Expires`-driven refresh** — closes the release-bound half of the quick-fixes trade-off honestly stated in the README. Compile `ubo-quick-fixes` network rules at refresh time with the (fixed, §3.3) Rust compiler into a reserved dynamic-rule range; ~30 rules against a 30,000 dynamic budget. Limits: `MAX_NUMBER_OF_UNSAFE_DYNAMIC_RULES` (5,000, Chrome 121+) for redirect/modifyHeaders actions; regex rules 1,000. Touches: SW refresh path, `lib.rs`. Effort M.
3. **SW-independent first paint for cosmetics** — register the generic CSS as a content-script `css` file via `registerContentScripts` (no message round trip, applies before the SW is awake), and per-hostname specific CSS the way uBO Lite does (one registration per domain bucket). Limits: registration count and size are not formally capped but each write is persisted; batch updates. Touches: SW index rebuild (emit CSS files to `chrome.storage`? No — files must be extension resources, so the specific half stays dynamic via `insertCSS` while the generic half becomes static at build). Effort M–L.
4. **Modifier parity that DNR already supports** — `$to=`/`$from=`/`$denyallow=`/`$method=` (§4.2, part of remediation), `$csp=` via `modifyHeaders` append of `content-security-policy` on `main_frame`/`sub_frame` (83 corpus rules; multiple CSP headers combine restrictively, which is the semantics uBO wants), `$redirect=` via a vendored resource library served with `redirect.extensionPath` and a `web_accessible_resources` entry (634+237+22 rules today get an empty `data:` body; `noopjs`/`noopframe`/`1x1.gif` unbreak sites), `$header=` via the `responseHeaders` condition (Chrome 128 — a floor decision), and `$redirect-rule=` by a build-time join: emit the redirect only when a co-matching block exists in the corpus (recovers a large share of the 486 skipped). Effort M each.
5. **Honest counters in packed builds** — `onRuleMatchedDebug` is unpacked-only, so today the popup shows "—". `declarativeNetRequest.getMatchedRules({tabId})` works in packed builds with the feedback permission (rate-limited to 20 calls / 10 min, last 5 minutes only); poll it on popup open per tab, as uBO Lite does. Touches: SW `GET_TAB_STATS`, popup. Effort S–M.
6. **Diagnostics view** — `GET_ERROR_REPORT`, the unknown-scriptlet counter, and the trust-gate refusals have no UI; the release checklist asks releasers to read them from the SW console. A read-only options tab plus a `chrome.storage.session` ring buffer for the logger so it shows the last N events on open. Effort S.
7. **Element zapper and "cosmetics off on this site"** — a temporary hide that writes no rule (uBO's zapper), and a per-site toggle equivalent to `@@||site^$elemhide` stored beside the allowlist. Effort S.
8. **Missing cheap scriptlets** — `noeval-if` (152 rules), `nowebrtc` (59), `nobab`/`nofab`/`popads-dummy` (58), `set-attr`, `href-sanitizer`, `xml-prune`, and wiring `jsonpath.js` into `json-edit`/`trusted-json-edit-*` (61 rules, 13 of them the current YouTube quick-fixes). Effort M total.
9. **Custom list subscriptions** — the most requested uBO feature. Prerequisite: the list half of the trust gate (provenance tagging at ingestion in `db.js` + `compile_active_filter_index`), which the 2026-08 §0 correctly identified as the blocker. Effort L.
10. **Allowlist and settings sync** — `chrome.storage.sync` (100 KB total, 8 KB/item, 512 items): the allowlist fits; settings do; user filters do not (keep local, export/import). Effort S.
11. **Per-rule user overrides via `declarativeNetRequest.updateStaticRules`** (Chrome 111): let the logger's rows offer "never apply this rule" without editing text, which is how uBO's logger workflow feels. Limits: 5,000 disabled static rule IDs per ruleset. Effort M.
12. **i18n** — `_locales/` + `chrome.i18n.getMessage`; mechanical. Effort M.

Genuinely impossible under MV3 (state it in the README's parity table rather than "❌ — see"): dynamic filtering matrix; CNAME uncloaking; `$replace=`/HTML filtering (`##^`) and any response-body inspection; `$ipaddress=`; exact `$strict1p/3p` (DNR's `domainType` is registrable-domain based); true `$popup` semantics (DNR has no window-open signal); `$urlskip=` beyond what `regexSubstitution` can express safely.

## 8. What Is Genuinely Well Built

**The harness grew the capabilities the last review asked for, and they are what made this review's P0 reproducible in minutes.** `sw-loader.mjs` boots a cold worker (`cold: true`), reboots on the same IndexedDB (`idb`), and serves packaged sources; `chrome-stub.mjs` now JSON-round-trips the bus in both directions and validates DNR schema the way Chrome does. §3.1 above is a twelve-line script on top of it.

**The corpus is a first-class test fixture.** Vendoring the expanded lists did more than fix the release race: `corpus-conformance.test.mjs` and this review's measurements run against the real 13,934-rule corpus offline, and every count in this document is reproducible by anyone with the checkout.

**Accountability in the build is exemplary.** `_currentDropSink`, the per-list skip logs, `assertStaticRulePriorityBands`, `verifyDnrBudget`, and the directory-granularity `commitStagedRules` swap are the reason §4.1/§4.2 could be stated as exact numbers with the offending lines attached.

**The CSP fix in PR #14 was done the right way** — an explicit `connect-src` naming three origins and fourteen inline styles moved into stylesheets, rather than `'unsafe-inline'`, with a test that pins both against the runtime list table and the lock. That is precisely the discipline §4.13 of 2026-07 asked for.

**The release workflow's privilege split** — read-only by default, write only in the tag-gated job, SHA-pinned actions, `env: TAG` instead of interpolation, the immutable-release guard — is textbook, and `build-artifacts.test.mjs` enforces each property so it cannot silently regress.

**`shared-utils.js` is a small, correct port of uBO's hard parts**: `initPattern`/`testPattern` with `!` negation, `parsePropsToMatch` including the `/[^$\w -]/` re-join, `collateFetchArguments`, `RangeParser`, `maskNative` backed by one `Function.prototype.toString` proxy, `proxyApply`/`wrapInstanceGetter`. The scriptlets that use it are the ones this review found nothing wrong with; §4.4 is what happens in the one file that does not.

**The JSONPath port documents its divergences and verified them differentially** (34 expressions × 6 documents and 200k random malformed inputs against upstream, per the commit). Unconsumed today (§5.13), but the engineering is the kind that should be wired rather than deleted.

**`set-constant`'s deferred-parent trap composes** (`trapDeferredParent` keeps the previous accessor and chains through it), which is what lets four YouTube rules defer on one missing `ytInitialPlayerResponse` — the commit found and fixed a real, subtle clobber.

**The README's quick-fixes section states a trade-off plainly instead of hiding it.** §4.5 shows the mitigation it relies on is not yet true, but the honesty is why that was findable.
